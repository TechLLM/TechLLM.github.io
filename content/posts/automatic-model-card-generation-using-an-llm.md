흩어져 있거나 없는 AI 모델 설명서를 읽기 쉬운 공통 양식으로 정리하거나 만들어 주는 방법을 시험한 논문입니다.

**무엇이 문제였나** — 모델 설명서는 제각각이거나 아예 없는 경우가 있어, 모델을 비교하고 안전하게 쓰기 어렵습니다.
**어떻게 풀었나** — 언어 모델에게 기존 설명서를 정리하게 하거나, 모델 저장소의 파일과 논문을 바탕으로 새 설명서를 쓰게 했습니다.
**그래서 뭐가 좋아졌나** — 재배치한 설명서는 정보와 배치를 거의 유지했고 반복 실행도 안정적이었습니다. 새 설명서를 만들 때 관련 논문이 가장 큰 도움이 되었지만, 없는 사실을 추정하거나 자료끼리 충돌하면 틀릴 수 있었습니다.

> 서로 다른 형식으로 적힌 제품 설명서를 한 가지 공통 양식에 맞춰 정리하는 것과 비슷합니다. 설명서가 없는 제품은 상자 안의 안내문과 기술 자료를 읽어 새 설명서를 만들지만, 자료가 서로 다르면 사람이 확인해야 합니다.

## 논문 정보

Tajkia Rahman Toma, Balreet Grewal, Cor-Paul Bezemer · University of Alberta · ACM (Manuscript submitted to ACM; arXiv:2608.24807v1) · 2026

## 왜 중요한가

모델을 쓰는 사람은 무엇을 할 수 있고 어떤 점을 조심해야 하는지 알아야 합니다. 설명서 작성을 자동화하면 더 많은 모델에 안내를 붙일 수 있지만, 내용이 진짜인지 확인하는 과정도 함께 필요합니다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| 체크리스트 정보 보존율 | **93.8%** | MCTidy 재구성 카드 48개의 카드별 정보 보존율 중앙값 |
| 올바른 섹션 배치율 | **98.1%** | 전체 1,440개 (하위)섹션 중 잘못 배치된 내용이 없는 섹션의 비율 |
| 환각이 확인된 (하위)섹션 비율 | **10.2%** | 48개 재구성 카드의 1,440개 (하위)섹션 중 수동 검토로 환각 또는 오해가 확인된 147개 섹션 |
| MCTidy 반복 실행 의미 일관성 | **0.97** | 세 실행의 세 쌍에 대한 문서 수준 cosine similarity를 카드별로 평균한 뒤 구한 48개 카드의 중앙값 |

## 어떻게 동작하나

먼저 Hugging Face에서 944,178개 모델을 수집하고 좋아요 수와 최근 한 달 다운로드 수를 기준으로 상위 1,000개를 고른 뒤, 영어·1,000단어 이상의 긴 설명서·기본 모델·중복이 아닌 조직 대표 모델 조건과 수동 검토를 거쳐 48개 카드를 선정했다. MCTidy는 원본 카드와 Mitchell et al.의 표준 템플릿을 Gemini 2.0 Flash Thinking에 제공해 내용을 재배치했으며 temperature는 0이었다. 체크리스트는 gpt-4o-mini-2024-07-18로 만든 뒤 두 저자가 세 차례 검토·수정했으며, 체크리스트의 중앙값 크기는 69개 항목이었고 수동 수정본과 원본의 평균 정규화 Levenshtein 거리는 0.03이었다. 정보 보존과 누락은 한 저자가 카드별 체크리스트를 대조하고 빠진 내용을 수동 보완하여 평가했다. 섹션 배치는 Gemini 2.5 Pro, OpenAI o4-mini, DeepSeek R1의 다수결로 판정한 뒤 두 저자가 표시된 사례를 검토했다. 총 1,440개 (하위)섹션 중 28개(1.9%)에서 잘못된 배치가 확인됐다. 환각과 오해도 체크리스트와 원문을 대조해 수동으로 수정했으며, 147개 섹션(10.2%)에서 확인됐다. 반복 안정성은 같은 설정으로 MCTidy를 세 번 실행하고 allenai/specter 임베딩의 cosine similarity를 비교했다.

MCGenie는 기존 모델 카드를 저장소 자료에서 제거한 뒤 저장소 파일과 관련 논문을 Gemini 2.5 Pro에 제공하여 같은 11개 섹션의 표준 템플릿으로 새 카드를 만들었다. 입력 한도를 넘지 않아 처음 생성된 카드는 26개였다. 실패한 22개 중 18개는 tokenizer.json과 일부 대형 설정 파일을 요약해 생성했고, 남은 4개는 중복 vocab.json 3개와 대형 노트북 1개를 제외해 처리했다. 생성 카드는 재구성·수동 검증된 대응 원본 카드와 specter 임베딩의 cosine similarity로 비교했으며, 문서 수준 평균과 중앙값은 모두 0.9였다. 사실 정확도는 Gemini 2.5 Pro와 Claude Sonnet 4.5를 기본 심사원으로 사용하고, 두 모델이意见을 달리하면 GPT-5가 세 번째 심사원이었다. 입력 토큰 문제를 피하기 위해 심사는 카드에 인용된 저장소 파일을 대상으로 했고, 오류로 표시된 판정을 모두 사람이 직접 재검증하지는 않았다. 본문은 남은 카드들의 평균 오류 섹션 수가 1.41, 중앙값이 1이라고 보고했다. 입력 자료 민감도는 파일 유형별 인용 빈도와 각 유형을 제외한 재생성 실험으로 평가했다. 논문이 있는 26개 저장소에서는 모두 논문을 인용했고, 설정 파일이 있던 46개 저장소에서도 모두 설정 파일을 인용했다. 토크나이저 파일은 43개 저장소에 있었지만 34개(79.1%)에서만 인용됐다. 체크리스트 수와 누락 수의 Pearson 상관은 유의하지 않았다(p = 0.1310).

핵심 수식:

```
\operatorname{sim}(A,B)=\frac{\mathbf{e}_A\cdot\mathbf{e}_B}{\|\mathbf{e}_A\|\,\|\mathbf{e}_B\|},\quad R=\frac{N_{\mathrm{present}}}{N_{\mathrm{total}}}\times100\nd_{\mathrm{miss}}(A,B)=\frac{\operatorname{Lev}(A,B)}{|B|},\quad d_{\mathrm{extra}}(A,B)=\frac{\operatorname{Lev}(A,B)}{|A|}
```

A와 B는 비교하는 모델 카드 버전이며, e_A와 e_B는 allenai/specter로 만든 비교용 임베딩이다. R은 카드별 체크리스트에서 존재로 판정된 항목 수를 전체 항목 수로 나눈 보존율이다. A는 MCTidy 재구성 카드, B는 누락을 수동 보완하거나 환각·오해를 수동 수정한 카드라고 할 때, 누락 거리는 완료본 길이 |B|로, 추가·오해 거리는 재구성본 길이 |A|로 정규화한다.

## 한계와 주의할 점

- 표본이 Hugging Face 상위 모델 중 길고 영어로 된 카드, 기본 모델, 조직별 대표 모델을 고른 48개에 한정돼 있어 짧거나 비영어권 카드와 일반 저장소에 결과를 그대로 일반화하기 어렵다.
- MCTidy의 누락·환각 판정에는 체크리스트와 사람의 수동 해석이 사용돼 주관성이 남는다. MCGenie의 사실 오류로 표시된 LLM jury 판정도 모두 수동으로 재검증하지 않았다.
- 저장소 파일이 서로 충돌하거나 오래된 경우 생성 문장과 인용 출처가 어긋날 수 있다. 실제로 출처 간 수치 불일치가 오류 원인으로 관찰됐다.
- MCGenie 입력 한도 때문에 처음에는 26개만 생성됐고, 이후 파일 요약과 제외를 통해 나머지를 처리했다. 특히 노트북 제거는 사용 예시 정보의 손실로 이어질 수 있다.
- 의도 사용자, 윤리 고려, 동기·권고처럼 해석이 필요한 설명은 근거 없는 추론이 끼기 쉽고, MCGenie에서도 해석 중심 섹션의 유사도가 상대적으로 낮았다.
- 의미 유사도는 사실 정확도를 대신하지 않는다. 원본과 생성 카드가 모두 빈 섹션이거나 비슷한 정형 문장을 공유하면 높은 점수를 받을 수 있다.
- 템플릿 설명을 실제 근거처럼 복사하거나, 대상 사용자·윤리 실천·데이터 사용 이유를 자료에 없이 추정해 적는다.
- 서로 다른 저장소 파일이 같은 수치나 설정을 다르게 보고할 때 하나를 잘못 선택하거나, 인용을 다른 주장에 연결한다.
- 원문 내 '아래', '다음', '이것' 같은 지시어를 새 문서에 그대로 옮겨 존재하지 않는 항목을 가리키게 한다.
- 긴 토크나이저 파일이나 노트북을 줄이거나 제외하면 일부 사용법·설정·사용 예시 정보가 잃어버려지고, 생성 카드의 근거 없는 부분이 늘어날 수 있다.
- 관련 논문이 없거나 논문과 설정 파일의 값이 충돌하면 의미적으로 그럴듯한 문장을 만들면서도 인용한 근거와 일치하지 않는 내용을 남길 수 있다.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### 관련 논문을 우선 입력하고 기술 파일은 보조 자료로 배치

RQ2.3에 따르면 논문이 포함된 26개 저장소에서는 모두 논문을 인용했고, 설정 파일이 있던 46개 저장소에서도 모두 설정 파일을 인용했다. 반면 토크나이저 파일이 있던 43개 저장소 중 34개(79.1%)에서만 이를 인용했다. 관련 논문을 제외한 재생성 결과의 중앙값 유사도는 0.91로, 설정 파일을 제외한 0.95와 토크나이저 파일을 제외한 0.96보다 낮았다. 실제 파이프라인에서도 논문 확보 여부를 우선 확인하고 기술 파일은 선택적으로 보충하는 정책을 적용할 수 있다.

**적용 지점** — MCGenie 입력 수집·우선순위 설정

**기대 효과** — 관련 논문이 없는 카드에서 입력 부족을 미리 식별하고, 기술 파일이 상대적으로 덜 중요한 경우에는 입력 비용과 한도 부담을 줄일 수 있다.

### 모델 카드 주장과 저장소 출처를 항목별로 연결하는 검증 단계

MCGenie의 출처 인용 방식을 모델 카드 생성 파이프라인의 문장 단위로 확장한다. 각 생성 항목에 저장소 파일명과 확인 가능한 근거 구간을 붙이고, 같은 항목에 연결된 파일들이 서로 다른 값을 제시하면 자동 확정하지 않고 충돌 상태로 표시한다. 논문은 오류의 다수가 생성 내용과 인용 출처의 불일치에서 비롯됐고 저장소 파일 간 충돌도 관찰했다고 보고한다.

**적용 지점** — 모델 카드 생성 파이프라인의 주장 검증·출처 연결 단계

**기대 효과** — 출처와 주장의 불일치 및 저장소 내 상충 정보가 사실 오류로 이어지는 문제를 검토 단계에서 드러낼 수 있다.

### MCTidy 재배치 후 누락 체크리스트와 취약 섹션을 자동 검토

MCTidy를 기존 모델 카드의 표준화 단계에 적용한 뒤, 원문에서 만든 정보 체크리스트를 대조해 빠진 항목을 검토 대상으로 만든다. 사용 안내와 설명 문맥은 논문에서 반복적으로 누락된 유형이므로 별도 표시한다. Primary intended users와 Ethical Considerations는 환각이 자주 관찰된 섹션이므로, 이 두 부분은 원문 근거가 있는지 확인한 뒤 공개한다.

**적용 지점** — 기존 모델 카드의 표준화 및 게시 전 검토 단계

**기대 효과** — 논문 평가에서 정보 보존율 중앙값 93.8%, 올바른 섹션 배치율 98.1%를 보였으며, 체크리스트는 누락을 찾는 실무 검토에 활용할 수 있다.

### 큰 저장소 입력을 파일 유형별로 축약·선별하는 전처리

MCGenie 입력 구성 단계에서 큰 tokenizer.json은 논문에서 사용한 방식처럼 모델 유형, 어휘 크기, 일부 항목, 전처리·후처리 설정과 특수 토큰을 추출해 요약한다. 대형 인덱스·생성 설정 파일도 필요한 항목을 구조화해 넣고, 핵심 정보가 겹치는 vocab.json 등은 중복 여부를 확인한다. 노트북처럼 제거 시 사용 예가 사라질 수 있는 자료는 제외 사실을 기록해 검토자에게 보인다.

**적용 지점** — 저장소 파일 수집·요약과 LLM 입력 구성 단계

**기대 효과** — 처음 생성에 실패한 22개 저장소 중 18개는 파일 요약으로 처리했고, 남은 4개는 중복 어휘 파일 3개와 노트북 1개를 제외해 처리한 입력 한도 대응 경험을 활용할 수 있다.

| Phase 1 | 입력 자료와 표준 템플릿을 정리한다. | 관련 논문을 우선 수집하고 설정 파일과 토크나이저 정보는 보충 자료로 정리한다. 각 파일의 출처와 버전을 기록하고, 정보가 없으면 추정 대신 미제공으로 표시하도록 템플릿 규칙을 설정한다. | 생성에 사용할 근거와 빈 정보의 범위를 분명히 해 검토 가능한 초안을 마련한다. |
| Phase 2 | 재배치·생성 초안과 검증 절차를 연결한다. | 기존 문서는 MCTidy로 재구성하고, 문서가 없으면 MCGenie로 생성한다. 체크리스트로 누락을 확인하며, 특히 사용자·윤리·동기·권고 섹션과 출처 간 수치 충돌을 집중 검토한다. | 반복적인 문서 정리 작업을 줄이면서 논문에서 확인된 주요 오류 유형을 검토 흐름에 포함한다. |
| Phase 3 | 검증된 문서를 공개하고 갱신을 관리한다. | 사람이 확인한 카드만 게시하고 각 주장에 연결된 출처를 함께 보존한다. 저장소 파일이 변경되면 관련 카드 초안을 다시 생성해 변경된 주장과 빈 섹션을 검토한다. | 모델 정보가 바뀔 때 문서도 함께 검토할 수 있고, 사용자는 주장과 근거를 추적할 수 있다. |
