AI 모델 경쟁의 질문이 달라졌습니다. 이제는 누가 벤치마크에서 몇 점 더 받았는지만으로 승부를 가르기 어렵습니다. 같은 예산으로 얼마나 쓸 만한 결과를 내는지, 대화를 넘어 실제 업무를 끝낼 수 있는지, 사람과 얼마나 자연스럽게 호흡하는지가 더 중요해졌습니다.

조코딩의 주간 IT 뉴스에서 다룬 GPT-5.6, GPT-Live, Work, Grok 4.5, Muse Spark 1.1은 이 변화를 한꺼번에 보여줍니다. 제품 이름은 여럿이지만 흐름은 하나입니다. 더 똑똑한 답변 모델에서 더 싸고 빠르게 일을 처리하는 실행 도구로 무게중심이 옮겨가고 있습니다.

## GPT-5.6이 내세운 것은 최고 점수가 아니라 효율입니다

영상에서 GPT-5.6은 디자인 판단과 지식 업무가 크게 나아진 모델로 소개됩니다. 3D 게임, 구글 어스 형태의 서비스, 발표 자료처럼 코드와 시각 구성이 함께 필요한 작업에서 이전 세대보다 완성도가 높아졌다는 설명입니다.

눈여겨볼 대목은 비용입니다. 영상에 제시된 Artificial Analysis 비교에서는 최고 성능 모델과 종합 점수 차이가 작지만 작업 비용은 더 낮은 것으로 나타납니다. 벤치마크 하나만으로 모든 사용 환경을 설명할 수는 없습니다. 그래도 개발자와 기업에는 중요한 신호입니다. 모델 선택 기준이 “가장 높은 점수”에서 “이 품질을 얻는 데 얼마가 드는가”로 이동하고 있기 때문입니다.

실무에서는 모델 이름보다 작업 단위로 비교하는 편이 낫습니다. 같은 기획서, 같은 발표 자료, 같은 웹 앱을 여러 모델에 맡긴 뒤 다음 네 가지를 기록하면 됩니다.

- 결과물을 바로 쓸 수 있는 비율
- 사람이 고치는 데 걸린 시간
- 한 작업을 끝내는 데 든 비용
- 오류가 났을 때 스스로 복구하는 능력

토큰 가격이 싸도 수정이 세 번 필요하면 실제 비용은 커집니다. 반대로 호출 가격이 조금 높아도 한 번에 끝낸다면 전체 비용은 줄어듭니다.

## Work는 채팅창을 업무 공간으로 바꿉니다

Work는 Codex의 실행 능력을 일반 사무 업무로 넓힌 제품에 가깝습니다. 영상에서는 Slack, Microsoft Teams, Google Drive, SharePoint, 이메일, 캘린더 같은 업무 자료를 연결하고, 조사부터 문서 작성까지 이어서 처리하는 방식으로 설명합니다.

이 변화가 중요한 이유는 접근성에 있습니다. 개발자는 이미 코딩 에이전트에 파일과 도구를 맡겨 복잡한 작업을 처리해 왔습니다. Work는 그 방식을 기획, 영업, 운영, 재무 같은 직무로 가져옵니다. 사용자는 명령어를 익히는 대신 채팅 화면에서 업무 맥락을 지정하고 결과를 확인합니다.

다만 연결할 수 있다는 것과 믿고 맡길 수 있다는 것은 다릅니다. 이메일 발송, 외부 문서 공유, 결제처럼 되돌리기 어려운 행동에는 승인 단계를 남겨야 합니다. 업무 자동화의 성패는 모델 지능뿐 아니라 권한 범위, 실행 기록, 실패 시 복구 절차에서 갈립니다.

## GPT-Live는 말의 내용보다 대화의 타이밍을 다룹니다

기존 음성 AI는 대체로 사용자가 말을 마치면 답하는 턴 방식이었습니다. GPT-Live는 서로 말이 겹치는 상황, 짧은 맞장구, 끼어들기처럼 실제 대화에서 흔한 신호를 처리하는 쪽으로 나아갑니다. 영상에서는 GPT-Live와 GPT-Live mini 두 모델, 한국어와 영어의 실시간 통역 시연도 소개합니다.

여기서 달라지는 것은 속도만이 아닙니다. 사람은 대화 중 “잠깐만요”, “그 부분을 다시 설명해 주세요”라고 자연스럽게 방향을 바꿉니다. 음성 모델이 이런 개입을 즉시 알아들으면 고객 상담, 언어 학습, 회의 보조, 현장 안내 서비스의 설계가 달라집니다.

그만큼 새로 확인할 문제도 생깁니다. 배경 소음 속에서 누구의 말을 따를지, 통역 중 빠진 내용은 없는지, 건강이나 금융처럼 민감한 대화가 어디에 저장되는지 따져야 합니다. 자연스러운 목소리가 정확성을 보장하지는 않습니다.

## Grok과 Meta의 합류로 경쟁 축이 더 늘었습니다

Grok 4.5는 소프트웨어 엔지니어링과 작업 처리 속도, 가격 경쟁력을 앞세웁니다. 영상에서는 초당 약 80토큰의 처리 속도와 6달러의 출력 토큰 가격이 언급됩니다. 특정 벤치마크의 우위는 시험 구성에 따라 달라질 수 있지만, 코딩 모델도 성능과 비용을 함께 겨루는 단계에 들어섰다는 점은 분명합니다.

Meta의 Muse Spark 1.1은 코딩, 컴퓨터 사용, 긴 맥락 처리에서 경쟁 모델과 견줄 만한 결과를 내세웁니다. 동시에 이전 Llama 계열과 달리 공개 가중치 모델이 아니라 앱과 API 중심으로 제공된다는 설명도 나옵니다. Meta까지 폐쇄형 고성능 모델 경쟁에 힘을 싣는다면 개발자는 선택지가 늘지만, 특정 제공자에 묶일 위험도 함께 살펴야 합니다.

모델 표에서 1등을 고르는 일보다 교체 가능한 구조를 만드는 편이 오래갑니다. 프롬프트, 평가 항목, 입력 자료를 모델과 분리해 두면 가격이나 성능이 바뀌었을 때 다른 모델로 옮기기 쉽습니다.

## “일자리 90% 대체”는 그대로 받아들이면 안 됩니다

영상 후반에는 KDI의 ‘AI와 공존하는 새로운 노동시장 정책’ 논의가 등장합니다. 자극적인 기사 제목만 보면 2030년에 일자리 90%가 사라질 것처럼 읽힐 수 있습니다. 다만 영상에서 인용한 핵심은 현재 일자리의 90% 이상에서 일부 업무를 기술적으로 자동화할 수 있다는 전망입니다.

업무의 일부를 자동화할 수 있다는 말과 직업 전체가 사라진다는 말은 다릅니다.

그래도 충격이 작다는 뜻은 아닙니다. 자료 조사, 초안 작성, 일정 조율처럼 신입이 경험을 쌓던 업무부터 자동화되면 경력 사다리의 첫 칸이 약해질 수 있습니다. 기업이 AI를 인원 감축에만 쓰는지, 사람이 더 어려운 일을 맡도록 돕는 도구로 쓰는지에 따라 결과도 달라집니다. 평생 학습과 사회 안전망뿐 아니라 초급 인력이 성장할 수 있는 업무 설계를 함께 논의해야 하는 이유입니다.

## 개인에게 필요한 것은 모델 추격보다 작은 실험입니다

새 모델 발표를 모두 따라잡기는 어렵습니다. 대신 반복해서 하는 일 하나를 고르면 됩니다. 발표 자료 초안, 고객 문의 분류, 시장 조사, 이메일 정리처럼 결과를 확인하기 쉬운 업무가 좋습니다.

작게 시작해 보세요. 기존 방식으로 걸린 시간과 비용을 적고, AI에 맡긴 뒤 수정 시간까지 다시 잽니다. 한 번의 멋진 시연보다 세 번 반복했을 때 안정적으로 줄어든 시간이 더 믿을 만한 지표입니다.

1인 창업에도 같은 원칙이 통합니다. AI가 아이디어를 대신 책임지지는 않습니다. 다만 시제품 제작, 홍보 문안, 고객 반응 정리의 비용을 낮춰 더 많은 가설을 시험하게 해 줍니다. Google Workspace CLI처럼 이메일과 문서 도구를 에이전트에 연결하는 방법도 영상에서 실제 업무를 줄인 사례로 소개됩니다. 처음부터 모든 권한을 열기보다 읽기 전용 작업부터 연결하고, 외부 발송에는 사람의 승인을 남기는 편이 안전합니다.

이번 경쟁에서 가장 눈여겨볼 변화는 모델 이름이 아닙니다. AI가 답을 만드는 도구에서 일을 끝내는 도구로 가까워지고 있다는 점입니다. 그래서 사용자에게 필요한 능력도 좋은 질문을 쓰는 데서 멈추지 않습니다. 목표를 작게 정의하고, 결과를 검증하며, 실패했을 때 멈추게 하는 운영 감각이 더 중요해지고 있습니다.
