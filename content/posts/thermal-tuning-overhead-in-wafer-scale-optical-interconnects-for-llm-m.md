AI 학습을 여러 컴퓨터로 나눠 처리할 때 생기는 통신 대기 시간을 줄이는 방법과 그 대안의 가능성을 분석한 연구다.

**무엇이 문제였나** — 여러 컴퓨터가 AI 학습을 나누어 처리할 때, 필요한 데이터만 골라 보내더라도 통신이 늦으면 전체가 기다린다.
**어떻게 풀었나** — 연구진은 계산 중 생기는 열 때문에 통신 부품의 빛 파장을 다시 맞추는 데 얼마나 오래 걸리는지 계산과 통신 모델을 이어서 살펴봤다.
**그래서 뭐가 좋아졌나** — 전기 신호로 상태를 바꾸는 부품은 이 기다림을 크게 줄일 수 있으며, 축약 실험에서는 전체 처리 속도가 더 빨라졌다.

> 여러 주방이 음식을 나눠 만들지만, 재료를 옮기는 컨베이어가 열 때문에 잠깐씩 멈춘다고 생각해 보자. 컨베이어를 다시 맞추느라 생기는 기다림을 줄이면 주방 전체의 일이 더 빨리 끝날 수 있다.

## 논문 정보

Seongwon Yoon, Pin-Jun Chen, Shimeng Yu · Georgia Institute of Technology · arXiv preprint · 2026

## 왜 중요한가

AI의 크기가 커질수록 계산 능력만큼 데이터를 빠르게 옮기는 능력도 중요해진다. 통신 부품이 뜨거워져 제때 작동하지 못하면 충분한 대역폭을 갖춰도 전체 학습 시간은 길어질 수 있다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| Mixtral 8×7B 속도 향상 | **2.7×** | 4층 proxy에서 열 조정 정지 포함 시 무정지 기준 대비 정규화 반복 시간이 2.7배였으며, 정지를 제거하면 2.7배 속도 향상 |
| Qwen-MoE 14.3B 속도 향상 | **3.8×** | 4층 proxy에서 열 조정 정지 포함 시 무정지 기준 대비 정규화 반복 시간이 3.8배였으며, 정지를 제거하면 3.8배 속도 향상 |
| LLaMA-MoE 6.7B 속도 향상 | **3.3×** | 4층 proxy에서 열 조정 정지 포함 시 무정지 기준 대비 정규화 반복 시간이 3.3배였으며, 정지를 제거하면 3.3배 속도 향상 |
| Mixtral 8×7B 4층 평균 정지 시간 | **48.7ms** | 초기 환경 온도에서 상승하는 일회성 구간을 제외한 정상 상태 정지 창의 평균이며 각 all-to-all 통신 라운드 앞에 한 번 주입 |

## 어떻게 동작하나

연구진은 종단 간 ht-sim 네트워크 시뮬레이션과 과도 열 해석에 동일한 FlexFlow 작업 그래프를 사용했다. 작업 그래프의 전체 forward-and-backward 일정을 파이프라인 병렬도 4와 expert-parallel 차수에 따라 대표 디바이스의 연산 몫으로 나눴다. 연산 강도에 따른 GPU 전력은 roofline 계산으로 정당화한 모델링 가정이며, attention·expert FFN에는 700 W, gate에는 280 W, add-and-normalization에는 140 W, compute kernel가 없는 all-to-all에는 84 W를 배정했다. 모든 경계 조건과 물성값은 공개된 2.5D/3D co-packaged optics 특성에서 가져와 Ansys GPU/EIC/aPIC/interposer 적층 모델에 적용했다. 계산된 MRR 위치 온도 T(t)를 80 pm/K의 열광학 계수와 속도 제한 제어기에 넣어 잔류 detuning과 정지 구간을 구했고, 초기 175.0 ms의 일회성 상승 구간을 제외한 정상 상태 평균을 각 all-to-all 통신 라운드 앞에 한 번씩 주입했다. 기존 네트워크 모델의 all-to-all 이벤트당 350 ms 지속 시간은 그대로 유지했다. 성능 배수는 4층 proxy 결과이며, 전체 층 열 해석은 정지 시간이 증가함을 보여도 전체 규모 네트워크 시뮬레이션은 완료되지 않았다. 별도로 TCAD와 Ansys Lumerical을 이용해 HZO 게이트 LiNbO₃ 도파로의 전기장 유도 굴절률 변화와 약 1550 nm에서 TE/TM 모드 구속을 분석하고, 강유전체 조정은 통신 경로에서 지연을 무시할 수 있는 것으로 모델링했다.

핵심 수식:

```
Δλ_th(t) = (dλ/dT)[T(t) − T(0)]
ε(t) = |Δλ_th(t) − λ_track(t)|
communication stall if ε(t) > ε_max
```

T(t)는 aPIC의 MRR 위치 온도이고 T(0)은 기준 온도이다. dλ/dT는 실리콘 링의 열광학 계수 80 pm/K이다. λ_track(t)는 제어기가 추적한 파장 이동량이며 최대 추적 속도 Rctrl = 0.0625 K/ms, 즉 5000 pm/s로 제한된다.Representative Q = 8000에서 링의 FWHM은 193.8 pm이며, εmax는 그 10%인 19.4 pm로 설정되어 약 1 dB의 삽입 손실 페널티 경계에 해당한다.

## 한계와 주의할 점

- 핵심 종단 간 속도 향상 수치 2.7배·3.8배·3.3배는 각 모델의 전체 층 결과가 아니라 4층 작업 그래프의 proxy 결과다.
- 전체 층 열 해석에서는 평균 정지 시간이 Mixtral 173.9 ms, Qwen-MoE 68.3 ms, LLaMA-MoE 96.9 ms로 증가했지만, 전체 규모 네트워크 시뮬레이션은 Mixtral과 LLaMA-MoE에서 50분, Qwen-MoE에서 4.7시간의 제한 안에 완료되지 않아 전체 모델의 종단 간 배수를 제시하지 못했다.
- GPU 전력 자체의 실측 trace는 없고 연산 강도에 700 W, 280 W, 140 W, 84 W를 배정한 모델링 가정에 기초한다. roofline 계산은 이 가정의 상대적 타당성을 뒷받침하지만 실제 전력 변동을 재현하지는 않는다.
- 열 경계 조건과 물성값은 공개된 OIO3D 스택의 검증 자료에서 가져왔으므로 실제 웨이퍼 시스템의 냉각 방식, 재질, 패키징 및 전력 밀도 차이는 결과에 직접 반영되지 않는다.
- 강유전체 분석은 HZO-gated LiNbO₃ 도파로의 TCAD·광학 모델과 인용된 전환 속도·내구성 자료에 기초한다. HZO 조정을 기존 MRR 링크에 집적하고 반복 스위칭과 통신을 함께 실증한 결과는 아니다.
- 400 Gbps per-link 조건의 토폴로지 비교는 모든 토폴로지에 열 조정 지연을 주지 않은 최선의 경우다. 제안 구조의 stall-free 성능이 모든 모델과 구성에서 우월한 것은 아니며, 큰 속도 향상은 토폴로지 우위 자체가 아니라 정지 제거에서 나온다.
- 실제 열 프로파일, MRR의 열광학 계수, 제어기 추적 속도 또는 공정 편차 допу 오차가 모델 값과 다르면 정지 시간과 속도 향상이 달라질 수 있다.
- 강유전체 소자가 실제 패키지 온도에서 요구되는 반복 스위칭 횟수를 견디지 못하거나 잔류 분극과 파장 안정성이 저하되면 비휘발성 조정의 이점이 줄어든다.
- 전문가 선택이 특정 GPU와 PIC 영역에 집중되면 국소 열점이 형성되어 공진 파장 오차와 통신 정지가 커질 수 있다.
- 전체 층 또는 expert-parallel 차수가 큰 구성에서 현재 패킷 단위 웨이퍼 토폴로지의 inter-wafer gateway routing 비용이 급증하면 종단 간 검증을 완료하기 어려워진다.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### MoE 통신 라운드별 MRR 열 정지 예측기 추가

광 인터포저를 사용하는 MoE 학습 시스템의 네트워크 시뮬레이션 입력 단계에 논문의 열→파장 이동→속도 제한 추적 오차→정지 판정 체인을 추가한다. FlexFlow와 같은 작업 그래프에서 계산 구간의 전력 일정을 만들고 열 모델에서 얻은 T(t)를 사용해 Δλ_th(t)와 ε(t)를 계산한다. εmax를 넘는 구간만 각 all-to-all 통신 라운드의 선행 지연으로 반영해, 모든 패킷에 전파 지연을 더하는 방식과 구분한다. 실제 GPU 전력과 온도 측정값으로 전력 프로파일 및 열 매개변수를 보정한다.

**적용 지점** — MoE 네트워크 시뮬레이션의 통신 지연 모델

**기대 효과** — 논문은 네트워크 지연을 임의로 가정하지 않고 열 해석에서 도출했으며, 4층 proxy 시뮬레이션에서 모델별 평균 정지 46.8~48.7 ms와 정지 포함 정규화 반복 시간 2.7~3.8배를 보고했다.

### 전체 층 MoE 평가용 확장 네트워크 시뮬레이터 구축

논문의 네트워크 평가 단계에서 전체 패킷 라우팅을 매번 세밀하게 처리하는 비용을 줄이면서 대규모 all-to-all과 웨이퍼 간 게이트웨이 동작을 보존하는 확장 가능한 모델로 대체한다. 전체 층 작업 그래프와 열 모델에서 구한 정지 시간을 함께 적용해 각 모델의 실제 규모 반복 시간을 산출한다. 기존 4층 결과와 가능한 소규모 패킷 시뮬레이션을 비교해 모델 오차를 확인하고, 전체 규모 결과가 나오기 전에는 성능 배수를 proxy 결과와 별도로 표시한다.

**적용 지점** — 대규모 MoE 웨이퍼 네트워크 시뮬레이션

**기대 효과** — 현재 4층 proxy 결과는 정지 제거 시 2.7배, 3.8배, 3.3배 속도 향상이었지만 전체 층 네트워크 시뮬레이션은 Mixtral·LLaMA-MoE에서 50분, Qwen-MoE에서 4.7시간 안에 완료되지 않았다.

### HZO-gated LiNbO₃ 조정기의 학습 반복 수명 검증

LiNbO₃/HZO 기반 전기광학 조정기를 적용하는 패키지 검증 단계에서 논문의 stall-window 통계를 학습 반복당 필요한 분극 전환 횟수로 변환한다. 목표 학습 반복 수와 패키지 온도에서 전환 속도뿐 아니라 잔류 분극, 광 파장 안정성 및 사이클 수명을 함께 측정한다. 예측한 전환 횟수가 보고된 고온 내구성 범위를 넘는지 학습 전에 확인하고, 소자 열화에 따른 링크 detuning을 네트워크 모델에 반영한다.

**적용 지점** — 웨이퍼 광 인터포저의 HZO-gated LiNbO₃ 전기광학 조정 후보

**기대 효과** — 논문 추정치는 학습 반복당 3.0~5.9회 스위칭이며 10⁶회 반복에서 약 3~6×10⁶ cycles가 필요하다. 인용한 HZO 자료는 125 °C에서 10⁷회 이후에도 안정적인 잔류 분극을 보고했다.

## 단계별 도입 로드맵

| 단계 | 목표 | 액션 | 기대 효과 |
|---|---|---|---|
| Phase 1 | 목표 워크로드의 열·통신 기준선 구축 | 대상 MoE 모델의 forward/backward 작업 그래프와 통신 구간을 수집한다. 패키지 층 구성, 냉각 조건과 GPU 전력을 확보하고 MRR 온도·공진 파장 변화를 연결해 기준 정지 시간을 산출한다. | 설계 초기부터 링크 대역폭과 열 조정 대기 비용을 함께 비교할 수 있다. |
| Phase 2 | 조정 방식과 통신 토폴로지 후보 비교 | 전체 층을 포함할 수 있도록 확장 가능한 네트워크 모델에서 thermo-optic 방식과 LiNbO₃/HZO 전기광학 조정을 비교한다. 허용 detuning, 제어 속도, Q, 스위칭 횟수와 온도 조건을 바꿔 민감도를 평가한다. | 실제 구성에서 필요한 조정 방식과 대역폭, EP 배치의 선택 근거를 마련한다. |
| Phase 3 | 패키지 수준 시제품에서 예측 검증 | GPU/EIC/PIC 적층 시제품에서 열 주기, MRR detuning, 링크 오류, 통신 정지 및 강유전체 반복 스위칭을 같은 워크로드로 측정한다. 실측값으로 열·네트워크 모델을 보정한 뒤 학습 반복 횟수에 따른 내구성을 확인한다. | 시뮬레이션의 성능 이득이 실제 시스템의 학습 시간과 신뢰성으로 이어지는지 판단할 수 있다. |
