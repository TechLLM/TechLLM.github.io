반도체 조각을 쌓거나 연결하는 여러 설계 방식을 같은 공개 시험 문제에서 비교할 수 있도록 공통 모음을 만들었다.

**무엇이 문제였나** — 칩을 여러 조각으로 나누고 쌓는 설계가 늘지만, 연구 결과를 공정하게 비교할 공개 시험 문제가 부족했다.
**어떻게 풀었나** — 계산·메모리·입출력·아날로그 역할을 하는 가상 부품과 기판·연결 방식을 조합한 20개 공개 시험 문제를 만들었다.
**그래서 뭐가 좋아졌나** — 연구자들이 같은 입력과 조건으로 서로 다른 방법을 실행하고 결과를 비교해 후속 연구와 확장이 가능하도록 공통 기반을 제공한다.

> 새 자동차 엔진을 비교할 때 시험차와 주행 조건을 함께 정해야 어느 쪽이 유리한지 알기 쉽다. 이 논문은 여러 부품 구성과 연결 방식을 담은 공개 시험 문제를 만들어, 서로 다른 설계 방법을 같은 입력에서 비교하게 한다.

## 논문 정보

Rohan Soni, Jooyeon Jeong, Alexander Graening, Anthony Foo, Richard Chen, Puneet Gupta · University of California, Los Angeles, Department of Electrical and Computer Engineering · arXiv preprint arXiv:2608.25155v1 · 2026

## 왜 중요한가

새 설계 방법이 정말 나아졌는지 비교하려면 연구자들이 똑같은 입력과 조건을 사용해야 한다. 이 자료는 부품의 종류와 연결·적층 방식이 다른 상황을 함께 다뤄, 연구 결과를 재현하고 새로운 설계 문제로 확장하는 데 도움을 준다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| 공개 설계 사례 | **20개** | 논문이 제시한 전체 이종 2.5D/3D 벤치마크 설계 수 |
| 설계 범주 | **4개** | 기초 2.5D, 기초 3D, 복합 하이브리드, 모델 스트레스 테스트 범주 수 |
| 가상 활성 다이 템플릿 | **5개** | Compute Small, Compute Large, Memory DRAM, IO Controller, Analog Chiplet 템플릿 수 |
| 기판 템플릿 | **2개** | Organic substrate와 Silicon interposer 템플릿 수 |

## 어떻게 동작하나

저자들은 두 단계로 벤치마크를 구성한다. 1단계에서는 Compute Small, Compute Large, Memory DRAM, IO Controller, Analog Chiplet의 가상 활성 다이 5종을 정의한다. 각 코어 면적은 각각 약 20 mm², 250 mm², 50 mm², 10 mm², 15 mm²이다. 또한 본딩 피치가 약 110 µm인 Organic substrate와 약 45 µm인 Silicon interposer, 그리고 양면 연결을 가진 TSV 인터커넥트 다이를 정의한다. 2단계에서는 이 라이브러리 요소를 조합해 20개의 시스템 인 패키지 설계를 만들고, 기초 2.5D, 기초 3D, 복합 하이브리드, 모델 스트레스 테스트의 네 범주로 구분한다. 모든 설계는 임의의 적층 계층, 앞면·뒷면 연결, TSV 신호 통과, 매립 다이, 기판 라우팅 제약을 표현하는 CATCH XML로 작성하며, 자동 변환 프레임워크를 통해 산업 표준 3Dblox 설명으로 배포된다. 전체 설계와 지원 자료는 Dryad의 DOI 10.5061/dryad.76hdr7tb6에 공개되어 있다. 논문은 알고리즘의 배치·라우팅 성능이나 정량 결과를 보고하지 않는다.

## 한계와 주의할 점

- 제안 알고리즘과 기준 알고리즘을 직접 비교한 결과나 정확도·지연시간·배선 길이 같은 성능 수치가 없어, 벤치마크의 실효성을 정량적으로 판단하기 어렵다.
- CATCH XML에서 3Dblox로의 자동 변환에 대한 변환 정확도나 오류율을 보고하지 않아, 모든 사례의 구조와 제약이 보존되는지 별도 검증이 필요하다.
- 가상 다이와 대표 사례가 실제 제품의 세부 물리 특성, 제조 편차, 열·전력 제약을 모두 반영한다고 본문에서 검증하지 않는다.
- 공개 설계 사례가 20개로 한정되어 있으며, 새로운 칩렛 종류나 패키징 기술이 등장할 때 라이브러리와 사례를 계속 확장해야 한다.
- 입력 설계가 CATCH XML 또는 3Dblox의 계층·연결 표현과 맞지 않거나 변환기에 결함이 있으면, 변환 과정에서 연결 관계나 제약이 누락될 수 있다.
- D14처럼 라우팅 층을 1개로 제한한 혼잡 사례에서 설계 도구가 실행 가능한 배선 해를 찾지 못할 수 있다.
- 실제 공정의 피치·비용·조립 조건이 모델 가정과 다르면 시험 결과가 현장 설계의 비용이나 구현 가능성을 잘못 나타낼 수 있다.
- 새로운 적층 기술이나 연결 방식을 현재 XML 표현으로 충분히 기술하지 못하면 관련 설계 문제가 벤치마크에 올바르게 반영되지 않을 수 있다.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### CATCH에서 3Dblox까지 설계 변환 검증기 추가

CATCH XML을 3Dblox로 변환하는 단계에 구조 검증을 추가한다. 임의의 적층 계층, 앞면·뒷면 연결, TSV 통과 신호, 매립 다이, 기판 라우팅 제약을 변환 전후에 대조한다. 누락되거나 바뀐 항목은 설계 사례와 위치를 함께 보고한다.

**적용 지점** — CATCH XML에서 3Dblox로 이어지는 벤치마크 변환 단계

**기대 효과** — 논문은 정량적 변환 오류율을 보고하지 않는다. 구조 검증을 통해 사례 변환의 누락을 조기에 확인할 수 있다.

### 범주별 실행 가능성 및 혼잡 결과를 표준 기록

벤치마크 실행 흐름에서 각 사례의 배치·라우팅 실행 가능 여부와 혼잡 관련 산출물을 공통 결과 형식으로 기록한다. D14의 단일 라우팅 층 혼잡 사례를 포함해, 도구가 제약을 만족하지 못한 경우와 실행 자체가 실패한 경우를 구분한다.

**적용 지점** — 2.5D/3D 물리 설계 벤치마크 실행 및 결과 수집 단계

**기대 효과** — 논문에 보고된 알고리즘 성능 향상 수치는 없다. 동일한 스트레스 사례를 사용해 실행 결과와 실패 조건을 일관되게 비교할 수 있다.

### 비용·조립 스트레스 설계를 확장 테스트로 연결

비용·조립 관련 평가 흐름에 D15와 D16을 회귀 사례로 연결한다. D15에서는 CS의 수량이 다른 구성 요소와 달라지는 설정을, D16에서는 개별 본딩과 동시 본딩 비교 조건을 입력 변화로 추적한다. 새로운 조립 모델이 생기면 유사한 스트레스 사례를 추가한다.

**적용 지점** — 칩렛 비용 분석과 패키지 조립 공정 평가 단계

**기대 효과** — 논문은 비용 모델의 오차나 성능 향상 수치를 보고하지 않는다. 수량·본딩 조건 변화가 평가 입력에 반영되는지 확인할 수 있다.

## 단계별 도입 로드맵

| 단계 | 목표 | 액션 | 기대 효과 |
|---|---|---|---|
| 1단계 | 공개 설계를 실행 가능한 평가 환경에 연결한다. | Dryad에서 벤치마크 설명과 지원 자료를 확보하고, CATCH XML에서 3Dblox로 이어지는 자동 변환 경로를 확인한다. D0를 기준 사례로 삼아 계층·연결·기판 제약이 변환 후에도 보존되는지 점검한다. | 연구자가 같은 입력과 구조를 이용해 후속 실험을 재현할 기반을 갖춘다. |
| 2단계 | 설계 범주별로 도구의 동작과 실패를 측정한다. | 기초 2.5D·3D 사례에서 시작해 복합 하이브리드와 스트레스 사례까지 단계적으로 적용한다. 실행 가능성, 배선 혼잡, 설계 도구별 산출물을 같은 방식으로 기록하고 제약 만족 실패와 실행 실패를 구분한다. | 단순 사례에서 복합 사례로 확장할 때 문제가 발생하는 구조와 제약을 찾을 수 있다. |
| 3단계 | 실제 기술 조건과 연구 질문에 맞게 평가 범위를 확장한다. | 새 칩렛 유형과 패키징 제약을 라이브러리에 추가하고 변경한 설계 설명을 버전 관리한다. 모델 결과를 실제 설계 흐름의 자료와 대조해 타당성을 검토한다. | 벤치마크가 새로운 3D 집적 기술과 설계 문제를 다룰 수 있도록 확장된다. |
