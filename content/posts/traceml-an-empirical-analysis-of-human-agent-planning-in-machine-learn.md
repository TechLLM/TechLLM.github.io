이 연구는 사람과 AI가 Kaggle 대회에서 코드를 바꾸고 점수를 확인하는 과정을 비교해, AI의 작업 방식이 사람과 어떻게 다른지 살펴봅니다.

**무엇이 문제였나** — 마지막 점수만으로는 AI가 어떤 과정을 거쳐 그 결과에 이르렀는지 알기 어려웠습니다.
**어떻게 풀었나** — 어떻게 살펴봤나: 코드 버전마다 점수와 시간, 바뀐 작업의 종류를 기록해 사람과 AI의 과정을 비교했습니다.
**그래서 뭐가 좋아졌나** — 무엇을 발견했나: Codex는 비슷한 조정을 되풀이하고 MLEvolve는 방향을 자주 바꾸는 경향이 있었습니다. 사람의 작업 방식에서 가져온 지침은 일부 대회의 점수를 높였습니다.

> 요리를 하다가 결과가 기대에 못 미칠 때, 어떤 요리사는 다른 조리법을 시도하고 예전에 접었던 조리법을 다시 살펴봅니다. 이 연구는 실제 개발 기록을 통해 사람과 AI가 다음 시도에서 어떤 선택을 하는지 비교합니다.

## 논문 정보

Jiarui Yan, Weiwei Sun, Sijie Li, Wenhan Li, Yiming Yang · Carnegie Mellon University · arXiv preprint (cs.LG), arXiv:2608.26086v1 · 2026

## 왜 중요한가

AI가 더 나은 결과를 내는 데 필요한 것이 문장으로 알려 줄 수 있는 규칙인지, 과거 작업을 기억하고 다음 행동을 고르는 능력인지 생각할 근거를 제공합니다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| 사람 작업 기록 | **4,465개 trajectory** | Kaggle 대회 134개에서 수집한 공개 notebook 기록 |
| 대회별 비교 기록 | **430 + 207개 trajectory** | 7개 공통 대회의 사람 기록 430개와 Codex·MLEvolve 기록 207개 |
| 이전 접근 재시도 비율 | **9.1 / 0.2 / 0.0%** | 상위권 사람 / Codex / MLEvolve의 재시도 가능 버전 중 이전 접근을 다시 시도한 비율 |
| 계획 지침 적용 후 점수가 오른 대회 | **5/7개 대회** | 2개 대회는 반복 실행 간 오차 범위 안이었고, 점수가 하락한 대회는 없었음 |

## 어떻게 동작하나

연구진은 Meta Kaggle의 공개 기록에서 대회 134개의 사람 trajectory 4,465개를 만들고, 그중 7개 대회의 사람 기록 430개를 Codex와 MLEvolve의 기록 207개와 비교했다. 코드 버전마다 점수와 시간, 코드에 포함된 작업 상태를 기록하고, 버전 사이의 변경에는 행동 종류·의도·변경 크기·점수 변화를 붙였다. 전체 151,088개 버전과 전이를 라벨링했으며, 의도 라벨은 사람 검토 100건에서 81% 일치했다. 행동 분포 차이는 PCA와 Jensen-Shannon divergence로 살펴보고, 전환·이전 접근 재시도·앙상블 행동도 분석했다. 불확실성 구간은 대회, 사람의 notebook 계보, agent 실행 단위를 고려해 계산했다. 마지막으로 약 1,000토큰의 계획 지침을 Codex에 적용하고, 같은 12시간 예산에서 기본 실행 및 지침 내용·반복 주기를 분리한 비교를 수행했다.

핵심 수식:

```
P_pivot = (pivot으로 분류된 전이 수) / (전체 전이 수)

Solution revisit: 현재 버전의 상태가 자신의 이전 버전과 Jaccard 유사도 ≥ 0.6이고, 직전 버전보다 이전 버전에 0.1 이상 더 유사하며, 중간에 유사도 < 0.5인 상태를 거친 경우

JSD(P‖Q) = ½ KL(P‖M) + ½ KL(Q‖M),  M = (P + Q) / 2
```

P_pivot은 전체 전이 중 모델 기반, 표현, 목표 또는 검증 방식의 방향을 바꾼 전이의 비율이다. Solution revisit는 논문이 정의한 이전 접근 재시도 조건을 문장으로 요약했다. JSD는 두 행동 분포 P와 Q를 비교하며 M은 두 분포의 평균이다.

## 한계와 주의할 점

- 사람 기록은 공개 Kaggle notebook 저장본에 기반하므로, 공개되지 않은 로컬 실험이나 저장되지 않은 작업은 포함하지 않는다.
- 사람은 수 주에 걸쳐 작업한 반면 agent에는 12시간 예산을 적용했다. 따라서 사람 데이터는 통제 집단이 아니라 공개된 작업 방식의 참고 분포로 해석해야 한다.
- agent 비교는 7개 대회와 Codex·MLEvolve 두 scaffold에 한정되어 있다. 다른 대회나 개발 환경으로 결과를 일반화하는 데 주의가 필요하다.
- notebook 계보와 코드 재사용, MLEvolve의 공유 search node 때문에 기록 간 의존성이 있다. 연구는 이를 고려해 불확실성 구간을 계산했다.
- 계획 지침을 적용한 Codex의 주된 작업 방식 전환 비율은 2.2%로, 사람 집단의 13.2~14.1%보다 낮았다. 지침만으로 사람과 비슷한 작업 리듬을 만들지는 못했다.
- Codex의 좁은 반복: 기존 앙상블의 가중치나 제출 후처리를 계속 조정해도 점수가 달라지지 않을 수 있다.
- MLEvolve의 잦은 전환: 전환 비율은 58%였지만, 전환 뒤 세 단계의 평균 점수 변화는 matched human +0.089, MLEvolve −0.008이었다.
- 점수 회복과 과거 접근 재시도의 혼동: Codex는 점수 하락의 89.0%를 회복했지만, 이전 접근을 다시 시도한 비율은 0.2%였다.
- 규칙의 과도한 적용: 단일 hold-out 검증을 금지한 지침을 그대로 따르면, 상위권 사람도 사용하는 해당 방식이 Codex에서는 0%가 될 수 있다. 논문은 이를 사람의 약 25% 사용 비율과 비교해 지침의 한계를 설명한다.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### 이전 작업을 찾아 재사용하는 장기 기억

논문의 solution revisit 정의를 검색 기준으로 참고한다. 코드 상태, 점수, 변경 내용, 검증 방식과 저장된 모델 결과물을 연결해 둔다. 점수가 정체될 때 현재 상태와 비슷한 과거 버전을 찾고, 그때의 점수 변화와 재사용할 수 있는 결과물을 함께 보여준다. 이 기억 검색 아이디어 자체는 논문에서 실험하지 않았다.

**적용 지점** — 장시간 ML 개발 에이전트의 과거 시도 검색

**기대 효과** — 상위권 사람의 이전 접근 재시도 비율은 9.1%, Codex는 0.2%, MLEvolve는 0.0%였다. 격차를 줄일 수 있는지는 별도 실험이 필요하다.

### 점수 변화를 고려하는 방향 전환 제어

전환마다 바뀐 작업 종류와 점수 변화를 기록하고, 전환 뒤 세 단계의 결과를 기준으로 그 방향을 이어갈지 살펴본다. 전환이 적은 경우와 지나치게 잦은 경우를 구분해 대응한다. 논문은 이러한 제어기를 직접 평가하지 않았으므로 제안된 후속 아이디어다.

**적용 지점** — 실험 분기의 방향 선택

**기대 효과** — 논문에서 사람·Codex·MLEvolve의 pivot 비율은 각각 25%·9%·58%였고, pivot 뒤 세 단계의 평균 변화는 matched human +0.089, MLEvolve −0.008이었다.

### 검증과 앙상블 지침을 실행 과정에 반영

논문의 계획 지침은 K-fold 검증, 이른 앙상블, out-of-fold 예측 저장 등을 권한다. 이를 확인할 때 행동을 했는지만 볼 것이 아니라, 실제로 새로운 모델이 추가됐는지와 점수가 어떻게 바뀌었는지도 기록한다. 논문은 계획 지침의 일부 효과를 Codex에서 평가했지만, 이 실행 계약 방식 자체는 평가하지 않았다.

**적용 지점** — 모델 실험의 실행 점검

**기대 효과** — 계획 지침 적용 후 7개 대회 중 5개에서 점수가 개선됐고, 2개는 실행 간 오차 범위 안이었으며, 하락한 대회는 없었다.

### 예측값과 모델 결과물 저장

논문은 out-of-fold 예측값과 모델 결과물의 저장을 계획 지침에 포함한다. 이를 실험 버전과 연결하면 과거 접근을 다시 살펴볼 때 같은 결과물을 재사용할 수 있다. 학습 비용이나 실행 시간 절감 효과는 논문에서 수치로 평가하지 않았으므로, 이를 확인하려면 별도 비교가 필요하다.

**적용 지점** — 모델 학습 결과물 보관과 재사용

**기대 효과** — 논문은 실행 시간이나 token 절감 수치를 제시하지 않았다. 결과물 재사용이 실제로 비용을 줄이는지는 후속 실험으로 확인해야 한다.

## 단계별 도입 로드맵

| 단계 | 목표 | 액션 | 기대 효과 |
|---|---|---|---|
| 1단계 | 코드 버전과 점수, 변경 내용을 함께 기록 | 각 버전에 시간, 점수, 코드 차이, 작업 종류와 점수 변화를 연결한다. 작업 계보도 저장해 반복되는 변경과 방향 전환, 과거 접근 재시도를 살펴본다. | 최종 점수만으로 알기 어려운 작업 과정을 비교할 수 있다. |
| 2단계 | 점수 변화와 과거 기록을 참고해 다음 작업 선택 | 점수가 정체될 때 다른 방향으로 전환할지, 과거 접근을 다시 시도할지 후보를 제안한다. 전환 뒤의 점수 변화를 기록해 그 방향을 이어갈지 판단한다. | 방향 전환의 횟수만 늘리는 대신 실제 점수 변화와 과거 접근 재시도를 함께 고려한다. |
| 3단계 | 같은 조건에서 작업 제어 방식을 비교 | 같은 backend, 도구, grader, 12시간 예산으로 기본 방식과 새 제어 방식을 비교한다. 작업 행동과 최종 점수를 함께 기록하고, 지침 내용과 반복 주기의 효과를 따로 살펴본다. | 논문에서는 계획 지침 적용 후 7개 대회 중 5개에서 점수가 개선됐고 2개는 오차 범위 안이었으며, 점수가 하락한 대회는 없었다. 새로운 제어 방식은 별도 비교가 필요하다. |
