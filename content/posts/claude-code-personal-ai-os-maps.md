## 핵심 요약

[MAPS 가이드](https://github.com/pavrus117/ai-os-maps-guide)는 Claude Code를 단순한 대화 도구가 아니라 파일 탐색, 상시 실행, 예약 작업, 현황 표시를 잇는 개인 AI 운영체제로 구성하는 방법을 제시한다. 핵심은 Memory, Agent, Pulse, Screen의 4개 층을 정해진 순서로 만들고, 각 단계의 결과를 사용자가 소유한 markdown 파일과 실행 기록으로 남기는 것이다. 저자의 작업 공간 실험에서는 메모리 지도를 썼을 때 같은 질문의 처리 시간이 1분 2초에서 30초로 줄고 토큰 사용량도 27.7k에서 16.8k로 감소했다. 독자는 화려한 화면부터 만드는 대신 정보의 위치, 실행 권한, 실패 한도부터 설계하게 된다.

### 한눈에 보기

- MAPS는 Memory, Agent, Pulse, Screen의 4개 층으로 구성되며 Memory부터 차례대로 만든다.
- 최상위 메모리 지도는 저자 사례에서 40줄이며, 실제 문서까지 2단계 안에 도달하도록 설계됐다.
- 동일 질문 실험에서 탐색 시간은 1분 2초에서 30초로, 토큰은 27.7k에서 16.8k로 줄었다.
- 두 컴퓨터의 파일 동기화와 예약 작업 확인 주기는 각각 5분으로 제시됐다.
- 저자는 대시보드가 전체 가치에서 약 20퍼센트를 차지한다고 평가하며 가장 마지막에 만들 것을 권한다.

## 네 층은 화면이 아니라 정보 구조부터 쌓는다

MAPS는 네 기능을 한꺼번에 설치하는 제품이 아니라 구축 순서를 정한 설계 틀이다. Memory는 정보 위치를 가리키고, Agent는 같은 작업 폴더를 두 컴퓨터에 놓으며, Pulse는 사람이 자리를 비운 동안 예약 작업을 실행한다. Screen은 앞선 세 층이 만든 파일과 기록을 읽어 보여주는 마지막 표시 장치다.

| 층 | 맡는 역할 | 최고 단계의 기준 |
|---|---|---|
| Memory | 업무 파일의 위치 안내 | 매일 검사되는 자동 생성 지도 |
| Agent | 노트북과 상시 실행 컴퓨터 연결 | 두 컴퓨터가 같은 폴더를 공유 |
| Pulse | 반복 업무 예약 실행 | 사용자 없이도 루틴 실행 |
| Screen | 파일과 실행 기록 표시 | 버튼 요청을 담당 컴퓨터에 전달 |

이 순서가 중요한 이유는 대시보드가 정보의 원본이 되어서는 안 되기 때문이다. 가이드는 대시보드가 사라져도 손실이 없도록 프로젝트 상태와 기록을 기존 파일에 남기고, 화면은 그 결과만 읽도록 제한한다. 저자가 화면의 가치를 약 20퍼센트로 본 것도 지도와 루틴이 먼저 작동해야 시각화가 실용성을 얻는다는 판단과 연결된다.

## 두 단계 파일 지도가 탐색 비용을 줄인다

여기서 Memory는 채팅 기록이 아니라 Claude Code가 올바른 파일을 찾게 하는 색인 구조다. 최상위 파일은 사실을 저장하지 않고 업무 영역별 안내 파일을 가리키며, 각 안내 파일이 실제 문서로 연결된다. 저자의 최상위 파일은 40줄이고, 제시된 작성 규칙은 최상위 지도를 60줄 미만, 영역별 안내 파일을 80줄 미만으로 제한한다.

| 조건 | 처리 시간 | 읽기와 쓰기 토큰 |
|---|---:|---:|
| 메모리 지도 없음 | 1분 2초 | 27.7k |
| 메모리 지도 있음 | 30초 | 16.8k |

이 수치는 저자가 새 Claude Code 세션 두 개에 같은 질문을 던진 단일 작업 공간 사례다. 지도 적용 뒤 토큰은 약 40퍼센트 줄었고 속도는 약 2배 빨라졌지만, 두 번째 실행에서는 읽기량 차이가 더 작았다고 원문도 밝힌다. 따라서 일반적인 성능 보장으로 확대하기보다 파일 탐색 경로를 줄였을 때 얻을 수 있는 사례 증거로 읽어야 한다.

지도에는 같은 사실을 두 곳에 쓰지 않는다는 규칙이 붙는다. 매일 실행하는 검사기는 연결된 경로가 실제로 존재하는지, 영역별 파일에 정해진 6개 구역이 있는지, 어느 지도에도 포함되지 않은 프로젝트 폴더가 있는지를 확인한다. 파일을 옮긴 순간 안내 파일도 함께 갱신해야 2단계 탐색 구조가 오래 유지된다.

## 상시 실행 자동화는 권한과 실패 한도로 묶는다

Agent 층은 노트북과 항상 켜진 두 번째 컴퓨터에 같은 폴더를 두는 구성이다. 가이드의 저자는 Hostinger VPS를 사용하며 git 기반 스크립트가 양방향으로 5분마다 변경 사항을 동기화하도록 제안한다. 이 구성이 마련되면 노트북을 닫아도 두 번째 컴퓨터가 같은 메모리 지도와 기술 파일을 읽을 수 있다.

상시 실행 컴퓨터에는 관리자 권한이 없는 계정을 만들고, Tailscale 같은 사설망에 먼저 연결한 뒤 공개 인바운드 연결을 차단하도록 안내한다. 서버에서 동작하는 Claude Code 설정은 전송, 공유, 삭제 도구를 막아 이메일을 작성할 수는 있어도 직접 보내지는 못하게 한다. 구독 인증과 외부 실행 도구의 허용 범위는 제공자마다 다를 수 있으므로 실제 구축 시점의 공식 약관을 다시 확인해야 한다.

Pulse는 루틴 이름, 일정, 실행 컴퓨터, 허용 도구, 최대 실행 횟수, 제한 시간, 출력 위치를 하나의 등록 파일에 적는 방식이다. 두 컴퓨터가 공유하는 실행기는 5분마다 기한이 된 루틴을 찾고, 실행 시각과 이름, 모델, 실행 횟수, 비용, 상태를 한 줄씩 추가한다. 일일 실행 상한과 짧은 구간의 상한을 함께 적용해 잘못 반복되는 작업이 한 달치 사용량을 밤사이 소모하지 못하게 하는 구조다.

첫 사례는 사용자가 일어나기 전에 밤사이 발생한 일, 오늘의 마감, 답을 기다리는 사람을 정리하는 아침 요약이다. 선택 기능인 Telegram 봇은 사용자 본인의 채팅 식별자만 허용하고 음성을 텍스트로 바꾼 뒤 질문, 메모 추가, 오늘 계획 가운데 하나로 분류한다. 모든 메시지와 답변을 날짜별 파일에 남기고 앞서 만든 제한 프로필을 그대로 쓰는 것이 조건이다.

## 대시보드는 읽기 전용으로 마지막에 붙인다

Screen 층의 원칙은 보여주되 저장하지 않는 것이다. 대시보드는 다른 작업이 이미 작성한 JSON 파일을 읽고, 각 패널에 자체 시각을 표시하며, 오래된 값은 숨기지 않고 오래됐다고 표시한다. 데이터 폴더에는 쓰지 않고 공개 포트 대신 로컬 주소나 사설망에만 연결하며, 쿠키와 로그인 기능, 외부 JavaScript도 두지 않는다.

버튼이 필요한 최고 단계에서도 화면이 작업을 직접 실행하지 않는다. 사용자가 실행 버튼을 누르면 루틴 이름, 요청 시각, 요청자를 담은 작은 요청 파일만 대기 폴더에 만들고, 5분마다 확인하는 실행기가 담당 컴퓨터에서 이를 처리한다. 실행이 기록된 뒤 요청 파일을 제거하므로 화면과 실행 책임을 분리할 수 있다.

가이드의 확장 화면은 같은 노드 집합을 고리, 원, 영역, 연결, 시간선, 입체 궤도의 6가지 보기로 그린다. 그러나 저자는 이 시각화가 사람들이 눌러 보는 부분일 뿐 시간을 절약하는 핵심은 아니라고 선을 긋는다. 비용 사례도 기존 Claude 구독 외에 할인 당시 2년 약 140 미국 달러였던 VPS와 월 몇 미국 달러의 음성 변환 비용으로 한정되므로, 현재 가격이나 모든 사용자의 총비용으로 일반화할 수 없다.

## 그래서 무엇이 달라지나

실무에서 가장 큰 변화는 Claude Code에 매번 파일 위치와 업무 맥락을 다시 설명하는 대신, 짧은 최상위 지도에서 필요한 문서까지 2단계로 안내할 수 있다는 점이다. 반복 작업은 5분 주기의 실행기가 맡고, 결과는 대화창이 아니라 사용자가 관리하는 파일과 로그에 남는다. 자동화가 실패해도 실행 한도와 기록이 있어 원인을 확인할 단서가 유지된다.

추측을 포함하면, 이런 구조는 프로젝트 수가 많고 작업 위치가 여러 폴더로 흩어진 사람에게 더 큰 효과를 낼 가능성이 있다. 반대로 파일 수가 적거나 예약 작업이 필요 없는 환경에서는 상시 실행 컴퓨터와 대시보드가 관리 부담만 늘릴 수 있다. 원문의 시간과 토큰 수치는 한 작업 공간의 비교이므로 도입 전에는 자주 묻는 질문 하나를 골라 지도 적용 전후를 직접 측정하는 편이 안전하다.

시작 범위도 작게 잡을 수 있다. 먼저 인터뷰 결과를 파일로 남기고, 하나의 최상위 지도와 영역별 안내 파일을 만든 다음, 매일 경로 검사만 실행하면 된다. 두 번째 컴퓨터, Telegram 봇, 6가지 그래프 화면은 그 구조가 실제 탐색 시간을 줄인다는 사실을 확인한 뒤 추가해도 늦지 않다.

## 정리

MAPS의 핵심은 AI 기능을 늘리는 데 있지 않고 정보의 원본, 실행 주체, 권한의 경계를 분명히 두는 데 있다. 파일 지도가 유용성을 증명한 뒤 상시 실행과 예약 작업을 연결하고, 화면은 끝까지 결과를 읽는 역할에 머물러야 한다. 이 원칙을 지키면 일부 구성 요소를 바꾸거나 제거해도 사용자가 소유한 기록은 그대로 남는다.
