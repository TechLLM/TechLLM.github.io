더 적은 FPGA 논리 칸으로 큰 회로를 합성하고, 모든 상태와 이동이 올바른지까지 검사한 논문이다.

**무엇이 문제였나** — 기존 공개 시험 자료는 회로 수가 적고 대부분 작은 회로에 머물러 있었다.
**어떻게 풀었나** — 저자들은 101개 회로를 다섯 크기로 모으고, 연결 구조를 유지하는 제작 방식과 기존 도구를 비교했다.
**그래서 뭐가 좋아졌나** — 제안 방식은 더 적은 논리 칸으로 빠르게 합성하고 모든 연결을 검사했다. 기존 도구가 끝내지 못한 가장 큰 회로들도 처리했다.

> 여러 정해진 상태가 조건에 따라 다음 상태로 바뀌는 제어 장치를 길 안내판에 비유할 수 있다. 제안 방식은 각 길과 연결 관계를 구조로 유지한 채 안내판을 짜는 것과 같다. 완성 뒤에는 모든 상태와 연결을 따라가 실제 안내판의 동작이 원래 규칙과 같은지 확인한다.

## 논문 정보

Samary Baranov, Danila Gorodecky · Holon Institute of Technology; INESC-ID, Instituto Superior Técnico, Universidade de Lisboa · IEEE Embedded Systems Letters · 2026

## 왜 중요한가

상태와 조건에 따라 움직이는 제어 회로는 통신 장비와 프로세서의 중요한 부분이다. 큰 회로를 더 적은 자원과 시간으로 만들 수 있다면, 더 많은 기능을 작은 칩에 담고 설계 결과도 빨리 확인할 수 있다. 이 논문은 기존 도구가 완료하지 못한 큰 회로까지 검증 가능한 결과를 내는지 확인한다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| Vivado 면적 기준 대비 LUT 감소율 | **45~66%** | SYNTLOG 면적 최적화와 Vivado Area Default 비교: 소형 54 대 98, 중형 123 대 288, 대형 696 대 2023 LUT. |
| 동일 one-hot 기준의 대형 LUT 감소율 | **43%** | Vivado Speed 200 MHz Performance의 1224 LUT 대비 SYNTLOG 면적 최적화의 696 LUT. 같은 one-hot 비교에서 소형은 54 대 56로 동률, 중형은 123 대 133이다. |
| 대형 그룹 평균 런타임 | **0.6~1.0 대 86~161초** | SYNTLOG 면적·지연 최적화는 0.6·1.0초이며 기능 검증을 포함한다. Vivado Area Default·200P·1GP는 86·88·161초이며 합성만 측정했다. |
| Vivado 미완료 설계 | **10/10개** | 거대 7개와 초거대 3개가 모두 수십 시간 후에도 Vivado 합성이 종료되지 않았다. |

## 어떻게 동작하나

저자들은 공개 HLS 및 RTL FSM 수집본에서 101개 HDL 상태기계 설명을 모아 소형부터 초거대까지 다섯 그룹으로 분류하고, 그룹별 평균 입력·출력·상태·전이 조건 수를 제시했다. Vivado 2022.2를 Kintex-7과 Kintex UltraScale+에서 실행했으며, 모든 설계는 독립 최상위 모듈로 합성하고 블록 RAM 추론을 끈 상태에서 LUT와 플립플롭만 비교했다. 두 장치의 LUT 수는 그룹 전체에서 1% 미만으로 달랐지만 논리 깊이는 같은 전략에서도 최대 25% 차 날 수 있어 표에는 Kintex-7 결과만 실었다. Vivado에는 총 여섯 최적화 전략을 적용했으며 Table III에는 Area Default, Speed 200 MHz Performance, Speed 1 GHz Performance의 세 전략만 보고했다. SYNTLOG는 M=6에서 면적 최적화와 지연 최적화를 각각 실행했으며 두 모드 모두 one-hot 인코딩을 사용했다. Vivado Area Default는 compact encoding을, 두 성능 전략은 one-hot을 사용하므로 같은 인코딩 조건의 비교와 면적 기준 비교를 구분해야 한다. 그룹 평균 LUT 수, 논리 깊이, 플립플롭 수, 런타임을 비교했으며, SYNTLOG의 모든 런타임에는 전체 상태·전이를 대상으로 하는 기능 시뮬레이션이 포함되고 Vivado 런타임에는 합성만 포함된다.

핵심 수식:

```
N_{FF}^{onehot}=S
N_{FF}^{binary}=\lceil\log_2 S\rceil
```

S는 상태 수이다. one-hot 인코딩은 상태마다 플립플롭 하나를 사용하므로 총 S개가 필요하고, compact binary 인코딩은 상태 번호를 표현하는 데 필요한 최소 비트 수인 ⌈log₂S⌉개를 사용한다. 논문의 FPGA 실험에서 SYNTLOG 두 모드는 모두 one-hot을 사용했으며, Vivado는 전략에 따라 compact 또는 one-hot 인코딩을 선택했다.

## 한계와 주의할 점

- 결과는 합성·기술 매핑 단계에만 한정되며 배치·배선 이후의 실제 지연, 장치 자원, 소비 전력은 평가되지 않았다.
- 그룹 평균만 제시되어 회로별 편차와 특정 설계의 성능 저하를 확인할 수 없다.
- Vivado는 소형·중형·대형만 완료했고 거대 7개와 초거대 3개에는 직접 비교 결과가 없다.
- SYNTLOG의 FPGA 실험은 one-hot으로 고정되어 있어 상태 수가 큰 회로의 플립플롭 비용과 전력 영향을 다른 인코딩에 일반화하기 어렵다.
- 통계적 유의성 검정, 신뢰 구간, 분산 자료가 없어 그룹 평균 차이의 안정성을 판단할 수 없다.
- 주요 절감률인 45~66%는 one-hot SYNTLOG와 compact Area Default를 비교한 값이다. 인코딩 효과를 통제한 해석은 Vivado의 one-hot 성능 전략과 비교해야 하며, 같은 one-hot 조건에서도 대형은 43% 적다.
- one-hot 상태 인코딩의 플립플롭 수가 상태 수와 같으므로, 상태가 매우 많은 회로에서는 레지스터 비용이 커질 수 있다.
- Vivado 결과가 없는 거대·초거대 회로에서는 LUT 수와 논리 깊이의 직접 비교가 불가능하다.
- 합성 후 논리 깊이가 배치·배선된 실제 FPGA의 타이밍 충족을 보장하지는 않는다.
- 전체 상태·전이 시뮬레이션은 기능 일치를 확인하지만 물리 구현의 연결성, 실제 전력, 보드 동작까지 확인하지는 않는다.
- LUT 폭이나 장치가 바뀌면 LUT 수와 논리 깊이가 달라질 수 있어, 6-input LUT에서 얻은 장치 독립성을 다른 조건에 그대로 적용할 수 없다.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### FSM RTL 출력 직후 전체 전이 검증을 승인 게이트로 연결

FSM 합성 파이프라인에서 SYNTLOG의 RTL 출력 직후에 내장 기능 검증을 승인 게이트로 둔다. 원본 FSM의 모든 상태와 전이에 대해 생성 회로의 다음 상태와 출력을 비교하고, 불일치가 하나라도 있으면 RTL을 승인하지 않은 채 입력과 생성 결과를 함께 보존한다. 논문은 이 검증이 SYNTLOG 런타임에 포함되며 가장 큰 사례에서도 완료를 허용했다고 보고한다.

**적용 지점** — FSM 합성 파이프라인의 RTL 생성 후 기능 검증 단계

**기대 효과** — 2,314개 상태와 351,351개 전이로 구성된 최대 사례에서 시뮬레이션을 포함해 30분 미만의 검증된 RTL을 생성했다.

### 대형 FSM 벤치마크를 합성 회귀 평가에 추가

합성 도구의 회귀 평가 입력에 논문의 소형·중형·대형·거대·초거대 그룹 구성을 반영한다. 그룹별 상태 수와 전이 조건 수를 기록하고 같은 LUT 폭과 기능 검증 조건에서 LUT 수, 논리 깊이, 플립플롭 수, 런타임을 저장한다. 시간 제한 안에 종료되지 못한 설계도 실패 상태로 남겨 확장성 변화를 추적한다.

**적용 지점** — FPGA 합성 도구의 벤치마크 회귀 평가 단계

**기대 효과** — 논문 벤치마크는 101개 설계를 다섯 규모로 나누며, Vivado가 완료하지 못한 거대 7개와 초거대 3개 설계도 포함한다.

## 단계별 도입 로드맵

| 단계 | 목표 | 액션 | 기대 효과 |
|---|---|---|---|
| Phase 1 | 대상 회로의 규모와 입력 자료를 정리한다. | FSM을 상태 수, 전이 수, 전이 조건 수, 입력·출력 수로 분류하고 HDL, ASM 또는 전이표 형식을 준비한다. 대상 FPGA의 LUT 입력 폭 M과 가용 플립플롭을 확인해 실험 조건을 고정한다. | 설계가 논문 벤치마크의 어느 규모와 비교 가능한지 파악하고 인코딩 관련 자원 제약을 미리 계산할 수 있다. |
| Phase 2 | 면적과 지연 목표에 따른 합성 결과를 같은 조건에서 비교한다. | 동일한 FSM을 SYNTLOG의 면적·지연 최적화와 Vivado의 Area Default 및 one-hot 성능 전략으로 합성한다. LUT 수, 논리 깊이, 플립플롭 수, 런타임을 기록하고 SYNTLOG 기능 검증 포함 여부와 Vivado의 인코딩 방식을 결과에 함께 남긴다. | 인코딩 차이와 검증 비용을 분리한 뒤 자원 절감과 논리 깊이 사이의 실제 설계 선택을 검토할 수 있다. |
| Phase 3 | 선정 설계를 실제 FPGA 구현으로 확인한다. | 후보 RTL을 배치·배선하고 타이밍, LUT·레지스터 사용량, 소비 전력 및 보드 동작을 측정한다. 논문의 합성 단계 수치와 물리 구현 수치를 별도 지표로 관리한다. | 합성 단계에서 나타난 이점이 실제 장치의 타이밍과 자원 제약에서도 유지되는지 확인할 수 있다. |
