단어가 비슷한 논문이 아니라, 내 문장을 실제로 뒷받침하는 논문을 찾아주는 AI 인용 비서다.

**무엇이 문제였나** — 기존 인용 추천은 제목이나 초록이 비슷한 진짜 논문을 잘 찾지만, 그 논문이 글의 주장과 논리적으로 맞는지는 자주 놓친다.
**어떻게 풀었나** — ReCite는 먼저 인용이 필요한 위치를 찾고, 그 자리에 왜 인용이 필요한지 판단한 뒤, 후보 논문이 정말 근거가 되는지 확인한다.
**그래서 뭐가 좋아졌나** — 후보가 맞지 않으면 이유를 따져 검색어를 다시 쓰고 재검색한다. 작은 4B 모델이 훨씬 큰 모델보다 엄격한 인용 정확도에서 더 좋은 결과를 냈다.

> 도서관에서 제목이 비슷한 책을 아무거나 가져오는 것이 아니라, 내가 쓰려는 한 문장에 꼭 맞는 근거가 들어 있는 책을 찾아주는 연구 보조 사서와 같다. 첫 검색이 빗나가면 왜 틀렸는지 보고 검색어를 고쳐 다시 찾는다.

## 논문 정보

Yuyang Huang, Bobo Li, Jiajia Song, Yuzhe Ding et al. · Wuhan University & National University of Singapore · arXiv preprint (cs.CL) · 2026

## 왜 중요한가

학술 글에서 인용은 주장의 받침대다. 실제로 존재하는 논문이라도 엉뚱한 주장에 붙이면 독자는 잘못된 근거를 믿게 된다. ReCite는 '진짜 논문인가'에서 멈추지 않고 '이 문장을 받쳐주는 논문인가'까지 확인한다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| End-to-End Strict F1 | **39.15%** | ReCite-SFT(CAP-8) vs DeepSeek-V4-Pro 31.77% (200개 테스트 단락) |
| End-to-End Lenient F1 | **55.14%** | 논리적으로 적절한 대체 논문을 허용한 평가, 최고 베이스라인 DeepSeek-V4-Flash 36.57% 대비 +18.57%p |
| CiteLocator Overall F1 | **66.37%** | 인용 위치 인식 모듈, 차상위 LLM 베이스라인 Qwen3.5-27B 48.04% 대비 +18.33%p |
| Position-Only F1 | **89.71%** | End-to-end 위치 탐지 평가, 최고 베이스라인 DeepSeek-V4-Flash 77.26% 대비 +12.45%p |

## 어떻게 동작하나

ReCite는 인용을 단순 유사도 검색이 아니라 '주장과 근거의 논리적 일치'를 확인하는 추론 과제로 재구성한다. 시스템은 Qwen3-4B 기반의 세 모듈로 나뉜다. CiteLocator는 문단에서 인용이 필요한 위치를 [#CITE#] 마커로 복원하고 Mandatory/Optional 필요성을 분류한다. QueryPlanner는 각 위치의 인용 의도를 추론하고 검색 키워드를 만들며, SFT 후 GRPO로 추가 학습된다. Master Brain은 observe-think-act 형식으로 후보 논문을 검증하고, 근거가 맞지 않으면 실패 이유를 분석해 키워드를 다시 쓰고 재검색한다. 학습 데이터는 10,893개 LaTeX source package에서 추출되며, 31,118건의 위치 인식 샘플, 7,079건의 질의 계획 샘플, 2,000건의 반영적 궤적으로 구성된다.

핵심 수식:

```
P = \frac{TP}{TP + FP},\quad R = \frac{TP}{TP + FN},\quad F1 = \frac{2 \times P \times R}{P + R}
```

논문 부록 B.2의 CiteLocator 평가 수식이다. P는 예측한 인용 위치 중 정답 비율, R은 실제 인용 위치 중 찾아낸 비율, F1은 P와 R의 조화평균이다.

## 한계와 주의할 점

- 전체 시스템이 컴퓨터과학 분야(ACL/EMNLP/CVPR/ICCV/NeurIPS 2024-2025) LaTeX 소스에 기반하므로, 인문학·의생명과학 등 다른 분야 일반화는 아직 체계적으로 검증되지 않았다.
- End-to-End Strict F1이 39.15%로 절대값은 높지 않다. 위치 탐지, 질의 생성, 검색, 검증이 모두 맞아야 정답이 되는 엄격한 평가라 단계별 오류가 누적된다.
- CiteLocator는 희소한 [#CITE#] 마커 학습을 위해 asymmetric cross-entropy와 새 tokenizer entry 등록을 사용하므로, 구현 환경 이전 시 토크나이저 처리가 중요하다.
- 검색 후보 수는 Figure 7 분석에 따라 k=8이 성능과 비용의 절충점으로 선택되지만, Semantic Scholar API와 후보 메타데이터 품질에 영향을 받는다.
- 현재 시스템은 텍스트 전용이며, 실제 논문 인용 판단에 중요한 차트·수식·의사코드 같은 시각 단서는 직접 검증하지 못한다.
- 초기 키워드가 지나치게 넓으면 검색 표류가 발생해 무관한 결과가 반환될 수 있다. 논문은 Figure 3과 Appendix C.2에서 이런 실패를 반영적 재검색 훈련 사례로 다룬다.
- CiteLocator가 Mandatory와 Optional 경계를 혼동하면 꼭 필요한 방법·데이터셋 인용이 빠지거나, 일반 배경 문장이 과도하게 인용될 수 있다.
- Lenient 평가는 LLM-as-a-Judge를 사용하므로, '논리적으로 대체 가능한 논문'의 판정이 평가자 모델의 편향이나 기준 모호성에 영향을 받을 수 있다.
- 반영적 궤적은 총 2,000개이며 그중 1,500개가 reflection-enhanced variant다. 학습 시 보지 못한 복합 의도나 새로운 분야에서는 재검색 전략이 약해질 수 있다.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### RAG 응답에 '논리 검증 게이트'를 옵션 스위치로 추가하기

장기 기억을 쓰는 에이전트의 검색 재순위 단계 직후, 또는 응답 생성 직전에 '답변 문장 vs 상위 k개 컨텍스트' 검증을 수행한다. 논문의 claim-evidence verification과 reflective re-retrieval loop가 핵심이며, 검증 실패 시 키워드 재작성 후 재검색을 트리거한다. 임베딩 유사도만으로 근거를 고르는 구조보다 논리적 정합성을 더 직접적으로 확인한다.

**적용 지점** — RAG 검색 재순위 단계, 응답 생성 직전 검증 단계

**기대 효과** — ReCite-SFT(CAP-8)는 Lenient F1 55.14%로 최고 베이스라인 36.57%보다 +18.57%p 높다. 다만 이는 인용 추천 벤치마크 결과이며 일반 RAG 환각 감소율로 직접 환산되지는 않는다.

### 에이전트 도구 호출에 '의도 추론 → 키워드 재작성' 단계를 끼워넣기

RAG 검색·API 호출 직전에 CAP-8 같은 의도 분류를 적용하고, 그 의도에 맞는 키워드 생성기를 호출한다. QueryPlanner(SFT+GRPO)는 R-F1 57.81%로 671B DeepSeek-V3의 58.63%에 근접한다. 모호한 의도에서 출발해 검색이 엉뚱한 방향으로 흐르는 문제를 줄이는 도구 호출 전처리 패턴으로 활용할 수 있다.

**적용 지점** — 에이전트 도구 호출 직전 의도 인식 단계

**기대 효과** — QueryPlanner(SFT+GRPO)는 R-F1 57.81%를 기록했고, 합성 키워드 품질 검증에서는 100개 샘플 기준 평균 정확도 90.6%, Cohen's κ 0.805가 보고됐다.

### 에이전트 하네스에 '반사적 재시도' 게이트를 내장하기

에이전트 하네스의 도구 호출 결과가 없거나 의미적 정합성 검증에 실패하면 observe-think-act 루프로 진입한다. Master Brain은 실패 귀인(<think>)을 작성하고 더 구체적인 키워드로 search_db_single을 다시 호출한다. 논문은 500개 gold path와 1,500개 reflection-enhanced variant로 총 2,000개 trajectory를 구성해 이를 학습시켰다.

**적용 지점** — 에이전트 하네스 도구 호출 실패 복구 단계

**기대 효과** — Master Brain 제거 시 Lenient F1이 47.10%에서 42.76%로 낮아져, 반영적 검증 루프가 후보 잡음 필터링과 실패 복구에 기여함을 보인다.

### 검색·요약 작업에 '위치 인식을 먼저' 패턴 채택하기

긴 본문에서 응답에 필요한 논리적 지점부터 식별하고, 그 구간에 대해 후속 검색·검증을 수행한다. 논문의 CiteLocator는 [#CITE#] 마커와 필요성 라벨을 함께 예측하며, Overall F1 66.37%로 Qwen3.5-27B의 48.04%를 크게 앞섰다. 이는 단순 청크 검색보다 더 세밀한 '근거 위치 예측' 패턴으로 응용 가능하다.

**적용 지점** — 장문 문서 요약·근거 추출 파이프라인의 위치 인식 단계

**기대 효과** — CiteLocator Overall F1 66.37%, 차상위 LLM 베이스라인 Qwen3.5-27B 48.04% 대비 +18.33%p.

### 검색 다양화를 위한 '의도 분류 기반 멀티 전략' 검색기

논문의 CAP-8 8종 인용 의도 분류(BG/MG/CMP/BS/MTD/VLD/EV/CRT)를 일반 검색 작업에도 매핑한다. 같은 질문이라도 배경 설명, 비교, 방법 근거 중 무엇이 필요한지에 따라 키워드와 재순위 기준이 달라질 수 있다. ReCite는 CAP-8 미세조정으로 ReCite-SFT 대비 Strict F1을 37.47%에서 39.15%, Lenient F1을 47.10%에서 55.14%로 끌어올렸다.

**적용 지점** — 다중 의도 검색·재순위 파이프라인

**기대 효과** — CAP-8 추가로 ReCite-SFT 대비 Lenient F1 +8.04%p, Strict F1 +1.68%p.

## 단계별 도입 로드맵

| 단계 | 목표 | 액션 | 기대 효과 |
|---|---|---|---|
| Phase 1 (0~3개월) | CiteLocator 모듈 단독 도입으로 인용 위치 인식 정확도 확보 | SFT로 학습된 4B CiteLocator를 사내 글쓰기 도구 플러그인으로 포팅하고, 사용자가 [#CITE#] 마커를 자동 삽입·삭제하는 워크플로우와 LaTeX 템플릿 호환성을 검증한다. | 인용 누락과 오삽입을 줄여 1차 초안 점검 시간을 단축한다. |
| Phase 2 (3~6개월) | QueryPlanner 통합으로 의도 인식 검색 활성화 | CAP-8 의도 분류를 결합해 8가지 라벨별 키워드 전략을 적용하고, 의미 검색 API 위에 의도 조건 필터를 추가하며, GRPO 학습 산출물을 반영한다. | 초기 검색 품질을 높여 재검색 비용과 사용자 확인 횟수를 줄인다. |
| Phase 3 (6~12개월) | Master Brain 반영적 검증 루프 통합 및 멀티모달 확장 검토 | observe-think-act 상태머신을 에이전트 하네스에 이식하고, 검증 실패 시 자동 재작성·재검색을 수행하며, 차트/수식 메타데이터 인식을 위한 VLM 모듈 PoC를 진행한다. | 첫 검색 실패가 곧 잘못된 인용으로 굳어지는 문제를 줄이고, 텍스트 밖 근거까지 다룰 기반을 만든다. |
