AI가 논문에 인용을 붙일 때, 단어가 비슷한 논문이 아니라 그 문장을 실제로 뒷받침하는 논문을 고르게 만든 연구다.

**무엇이 문제였나** — 문제: 기존 인용 추천은 실제 존재하는 논문을 가져오더라도, 그 논문이 문장의 주장을 제대로 뒷받침하지 못하는 경우가 많았다.
**어떻게 풀었나** — 해결: ReCite는 먼저 인용이 필요한 위치를 찾고, 왜 인용이 필요한지 파악한 뒤, 후보 논문이 그 주장과 논리적으로 맞는지 확인한다. 맞지 않으면 검색어를 고쳐 다시 찾는다.
**그래서 뭐가 좋아졌나** — 효과: 4B 규모 모델로 strict F1 39.15%, lenient F1 55.14%를 기록해 훨씬 큰 생성 모델과 일반 에이전트보다 좋은 인용 정확도를 보였다.

> 도서관 사서에게 책을 추천받는 상황과 비슷하다. 기존 방식은 제목이나 표지에 비슷한 단어가 있으면 책을 가져온다. ReCite는 먼저 내가 어떤 근거를 찾는지 확인하고, 책 내용을 살펴본 뒤, 맞지 않으면 질문을 다시 다듬어 다른 책을 찾아본다.

## 논문 정보

Yuyang Huang, Bobo Li, Jiajia Song, Yuzhe Ding, Chong Teng, Fei Li, Donghong Ji · Wuhan University · National University of Singapore · arXiv preprint (cs.CL) · 2026

## 왜 중요한가

AI가 학술 글쓰기를 돕는 일이 늘수록, 그럴듯하지만 엉뚱한 인용은 연구 신뢰를 크게 해친다. 이 연구는 인용을 '비슷한 문서 찾기'가 아니라 '주장을 뒷받침하는 근거 확인' 문제로 다루어, AI가 붙인 인용을 더 믿을 수 있게 만드는 방향을 제시한다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| End-to-End Strict F1 | **39.15%** | ReCite-SFT(CAP-8) 4B — 정확한 정답 논문까지 맞춰야 하는 평가 |
| End-to-End Lenient F1 | **55.14%** | ReCite-SFT(CAP-8) — 논리적으로 적절한 대체 논문도 허용한 평가 |
| CiteLocator Overall F1 | **66.37%** | 인용 위치 인식 — Qwen3.5-27B Direct 48.04% 대비 높은 성능 |
| QueryPlanner R-F1 (SFT+GRPO) | **57.81%** | 의도 기반 reasoning 생성 — DeepSeek-V3 671B의 58.63%에 근접 |

## 어떻게 동작하나

ReCite는 학술 인용을 유사도 검색이 아니라 주장-근거 검증 문제로 재정의한다. CiteLocator는 원문에서 인용이 필요한 논리적 위치를 [#CITE#] 마커와 Mandatory/Optional 라벨로 예측하며, 31,118개 샘플로 학습된다. QueryPlanner는 각 인용 위치의 의도를 추론하고 검색 키워드를 생성하며, 7,079개 고밀도 문단에서 만든 reasoning/keyword 데이터를 사용하고 SFT 후 GRPO로 추가 학습된다. Master Brain은 2,000개 observe-think-act trajectory를 통해 검색, 후보 검증, 실패 원인 분석, 재검색을 조율하도록 SFT된다. 추론 시 Semantic Scholar API에서 실제 후보 논문 메타데이터를 가져오기 때문에 존재하지 않는 논문 생성은 구조적으로 줄이고, 남는 핵심 문제인 오인용을 claim-evidence verification과 reflective re-retrieval loop로 다룬다.

핵심 수식:

```
P = TP / (TP + FP),  R = TP / (TP + FN)
F1 = 2 × P × R / (P + R)
K-Jac = |K_pred ∩ K_gt| / |K_pred ∪ K_gt|
```

P/R/F1은 인용 위치 또는 최종 인용 매칭의 정밀도·재현율·조화평균이다. K-Jac은 QueryPlanner 평가에서 예측 키워드 집합 K_pred와 정답 키워드 집합 K_gt의 Jaccard 유사도를 뜻한다.

## 한계와 주의할 점

- 4B 경량 모델은 ReCite가 목표로 하는 인용 워크플로 밖의 개방형 추론에서는 대형 범용 LLM보다 약할 수 있다.
- 현재 시스템은 텍스트 중심으로 동작하며, 논문에서 자주 쓰이는 차트·수식·의사코드를 근거로 한 인용 검증은 아직 다루지 못한다.
- 학습 데이터가 컴퓨터과학 주요 학회 논문에 집중되어 있어 인문학·의생명·법학 등 다른 분야에서의 일반화는 추가 검증이 필요하다.
- Strict F1 39.15%는 최고 성능이지만 절대값이 높지는 않으며, 저자별 인용 선택의 주관성과 다중 정답 가능성이 평가를 어렵게 만든다.
- 검색과 후보 확인이 외부 학술 데이터베이스 및 메타데이터 품질에 영향을 받으므로, 누락되거나 빈약한 메타데이터에서는 검증력이 떨어질 수 있다.
- 검색 드리프트: 초기 키워드가 너무 일반적이면 로보틱스·자율주행처럼 문맥과 다른 분야의 논문이 검색될 수 있으며, 이때 반성적 재검색이 실패하면 잘못된 후보가 남는다.
- 의도 분류 경계 모호성: BG와 MG, CMP와 CRT처럼 가까운 인용 의도는 문맥상 구분이 어려워 검색 키워드가 어긋날 수 있다.
- 동의어·약어 누락: GRPO와 Group Relative Policy Optimization처럼 같은 개념의 다른 표현을 놓치면 정답 논문 검색 가능성이 낮아진다.
- 메타데이터 부족: 후보 논문의 제목·초록·TLDR 정보가 빈약하면 Master Brain이 주장-근거 일치를 충분히 판단하기 어렵다.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### 의도 인지형 검색어 재작성 모듈을 RAG 재순위 단계에 결합

사용자 질의가 들어오면 먼저 검색 목적을 짧게 추론하고, 그 목적에 맞는 엔티티·동의어·분야 키워드로 검색어를 다시 만든다. 1차 검색 결과가 목적과 어긋나면 broad domain keyword에서 specific entity keyword로 좁혀 재검색한다. CAP-8 자체를 그대로 쓰기보다 도메인에 맞는 의도 taxonomy로 바꾸면 사내 문서 검색이나 코드 검색에도 적용할 수 있다.

**적용 지점** — RAG 검색 파이프라인의 query rewriting 단계, 검색 결과 재순위 직전

**기대 효과** — 논문에서는 QueryPlanner(SFT+GRPO)가 R-F1 57.81%를 기록해 671B DeepSeek-V3의 58.63%에 근접했다. 작은 모델도 의도 기반 검색어 생성에 특화하면 검색 품질을 끌어올릴 수 있음을 시사한다.

### 주장-근거 일치 게이트를 에이전트 최종 검증에 사용

에이전트가 결과를 내기 직전에 '이 답이 사용자의 요청과 논리적으로 맞는가'를 점검하고, 근거가 부족하거나 목적과 어긋나면 재작업 루프로 돌린다. ReCite의 observe-think-act 흐름처럼 관찰, 판단, 행동을 분리하면 검색 결과를 무비판적으로 사용하는 일을 줄일 수 있다.

**적용 지점** — 에이전트 작업 종료 전 자기검증 단계, 최종 답변 생성 직전

**기대 효과** — Ablation에서 Master Brain을 제거하면 Lenient F1이 47.10%에서 42.76%로 떨어졌다. 반성적 검증 루프가 논리적으로 적합한 후보를 걸러내는 데 기여한다는 근거가 된다.

### 검색 드리프트 자동 진단 + 키워드 정밀화 루프 패턴을 일반화

검색 결과가 원래 의도와 맞지 않으면 모델이 먼저 실패 원인을 설명하고, 분야명 수준의 넓은 키워드를 방법명·모델명·데이터셋명 같은 구체적 키워드로 바꿔 다시 검색한다. ReCite는 500개 gold trajectory와 1,500개 reflection-enhanced variant를 만들어 이 과정을 학습했다.

**적용 지점** — RAG/검색 에이전트의 1차 검색 후 결과 평가와 재검색 분기

**기대 효과** — 검색 드리프트를 조기에 잡으면 잘못된 컨텍스트가 후속 추론에 들어가는 일을 줄일 수 있다.

### SFT + GRPO 기반 경량 도메인 에이전트 템플릿

도메인별 reasoning trajectory를 합성해 SFT를 먼저 수행하고, 형식 준수·핵심 엔티티 회수·의도 정렬 같은 보상 항목으로 GRPO를 적용한다. ReCite에서는 QueryPlanner에 learning rate 5×10^-7, group size G=4를 사용했다.

**적용 지점** — 도메인 특화 에이전트의 fine-tuning 파이프라인, SFT 후 강화학습 단계

**기대 효과** — QueryPlanner(SFT+GRPO)는 R-F1 57.81%를 기록해 훨씬 큰 DeepSeek-V3 671B의 58.63%에 근접했다. 도메인 특화 학습이 모델 크기 부족을 일부 보완할 수 있음을 보여준다.

## 단계별 도입 로드맵

| 단계 | 목표 | 액션 | 기대 효과 |
|---|---|---|---|
| Phase 1 | 단일 도메인 파일럿 검증 | CiteLocator와 QueryPlanner를 기존 학술 RAG 파이프라인에 먼저 붙여 인용 위치 탐지와 검색어 품질을 점검한다. 내부 코퍼스에서 strict, lenient, position-only 기준을 나누어 평가한다. | 도입 전후의 인용 위치 정확도와 후보 논문 적합성을 확인해 실제 운영 가능성을 판단한다. |
| Phase 2 | 반성적 검증 루프 도입 | Master Brain의 claim-evidence verification과 re-retrieval loop를 활성화하고, 실패 시 키워드 재작성 정책과 후보 수를 조정한다. | 단순 유사도 검색에서 발생하는 오인용을 줄이고, 논리적으로 적합한 대체 인용을 더 잘 찾도록 만든다. |
| Phase 3 | 도메인 확장과 온프레미스 운영 | 분야별 용어와 인용 관습에 맞게 CAP-8 의도 분류와 검색어 생성을 재학습하고, 경량 모델의 양자화·내부 인덱스 구축을 검토한다. | 외부 API 의존도를 낮추고, 민감한 연구 초안도 내부 환경에서 처리할 수 있는 인용 검증 시스템으로 확장한다. |
