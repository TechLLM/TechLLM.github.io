여러 검색 모델을 비교할 때, 각 모델이 가져온 문서를 합쳐 한 번만 채점하고 그 점수를 계속 재사용해서 평가 비용을 크게 줄이는 방법이다.

**무엇이 문제였나** — 새 임베딩 모델이 나올 때마다 검색 품질을 다시 측정하려면 사람이 문서 수만 개를 새로 채점해야 해서 비용이 막대했다.
**어떻게 풀었나** — 모든 후보 모델이 가져온 문서의 합집합을 LLM 심사위원이 한 번만 채점하고, 새 모델이 추가될 때는 그 모델이 새로 가져온 문서만 추가로 채점한다.
**그래서 뭐가 좋아졌나** — 그 결과 4.9배 비용 절감, 65–80% 재사용률, 인간 채점과 거의 같은 순위(상관 0.69–0.95)를 production에서 확인했다.

> 여러 학생이 같은 도서관에서 서로 다른 책을 골라 추천한다고 하자. 모든 추천 도서를 사서가 한 번만 읽고 '관련 있음/없음' 점수를 매기고, 새 학생이 오면 그 학생이 새로 들고 온 책만 추가로 평가한다. 이미 점수가 매겨진 도서는 그대로 재사용되니 전체 채점량이 크게 줄어든다.

## 논문 정보

Max Nelson, Hanoz Bhathena, Aviral Joshi, Saket Sharma · JPMorganChase · arXiv preprint (arXiv:2609.02745v1) · 2026

## 왜 중요한가

RAG 시스템의 검색 모델 선택은 분기마다 vendor가 새 임베딩을 내놓을 때마다 반복되는데, 매번 처음부터 사람/AI로 채점하는 일은 작은 팀에는 감당되지 않는다. 이 방법은 이미 모은 채점 결과를 새 모델과도 즉시 비교할 수 있게 만들어, '후보 모델을 빠르게 골라내는' 실무 흐름을 가능하게 한다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| nDCG@10 Spearman 상관(인간 채점 vs LLM 채점) | **0.69–0.95ρ** | FiQA·TREC-COVID·NQ·FinRAGBench-V 4개 데이터셋에서 LLM 풀 채점 순위와 gold qrels 순위 사이 |
| 쌍(pairwise) 순서 보존율 | **97%** | qrels 부트스트랩 불확실성을 고려했을 때 LLM 채점이 보존하는 시스템 간 순서 비율 |
| 판정 재사용률 | **65–80%** | 4개 벤치마크(65–67%)와 production 62구성(79.6%)에서 새 시스템 추가 시 재사용된 판정 비율 |
| 평가 비용 절감 | **4.9×** | Production에서 62개 검색 구성을 4주에 걸쳐 평가 시 독립 평가 대비 비용 배수 |

## 어떻게 동작하나

검색 시스템 N개와 질의 집합 Q가 주어지면, (1) 각 시스템이 top-K 문서를 가져오고, (2) 그 문서들의 합집합 P(q)을 만들고, (3) 합집합 안의 고유 (q,d) 쌍에 대해 LLM 심사위원(GPT-4.1, temperature 0, 3단계 관련성 점수)을 한 번만 돌린 뒤, (4) 그 결과를 모든 시스템의 P@k·R@k·nDCG@k·MAP 계산에 재사용한다. 새 시스템이 추가되면 그 시스템이 가져온 새 문서(R_N+1(q) \ P(q))만 추가 채점하며, 기존 판정은 그대로 둔다. 핵심 가정은 심사위원 판정을 갱신하지 않고 시스템별 top-K를 고정한다는 점이며, 이 가정 하에 P@k·DCG@k는 풀 확장과 무관하게 정확히 보존되고, R@k·AP·nDCG@k는 질의 단위에서는 순서가 보존된다(매크로 평균은 경험적 검증).

핵심 수식:

```
C_{\text{pool}} = \sum_{q \in Q} \left| \bigcup_{i=1}^{N} R_i(q) \right| \quad\Rightarrow\quad \text{Reuse} = 1 - \frac{C_{\text{pool}}}{N \cdot |Q| \cdot K}, \quad \Delta C_{N+1} = \sum_{q} |R_{N+1}(q) \setminus P(q)|
```

C_pool은 풀링 후 필요한 총 판정 수, R_i(q)는 시스템 i가 가져온 top-K 문서, ∆C_{N+1}은 새 시스템 추가 시 추가로 발생하는 한계 비용 — 즉 그 시스템이 기존 풀에 기여하지 않은 새 문서만의 비용.

## 한계와 주의할 점

- 단일 심사위원(GPT-4.1)에 의존 — 다른 LLM·오픈웨이트 모델·도메인 특화 심사위원에 대한 보편성 검증은 TREC-COVID에서 Claude Sonnet 4.6 한 케이스만 수행됨.
- Frozen-model 가정 — GPT-4.1 체크포인트가 deprecate되면 연속성 확인을 위해 표본 재채점이 필요하며, 심사위원 드리프트에 대한 자동 보정 메커니즘이 없음.
- 단일 단계 검색기(dense/sparse/hybrid)만 평가 — 리랭커·cross-encoder·멀티스테이지 파이프라인에서는 문서 겹침 패턴과 점수 분포가 달라질 수 있어 본 결과의 외삽이 보장되지 않음.
- 매크로 평균 nDCG@k의 풀 확장 안정성이 이론이 아닌 경험적 증명에 그침 — FiQA·FinRAGBench-V에서 ∆ < 0.001 수준의 사실상 묶인 시스템 쌍에서 순서 역전이 관측됨.
- 스파스 qrels 데이터셋(NQ, FinRAGBench-V, ∼1 rel/query)에서 LLM의 더 넓은 관련성 정의가 절대 점수에 체계적 편향을 만듦(nDCG +17~+43%, recall −17~−37%) — 절대값 비교엔 부적합, 순위 비교엔 사용 가능.
- ∆MAP < 0.001 수준의 사실상 동률 시스템은 qrels·pseudolabel 양쪽 모두 구분 불가 — 이 방법은 '거의 같은 모델'을 가려내지 못함.
- 동률 묶음 처리 실패: 최상위 2개 시스템의 nDCG@10 차이가 ~0.000014 수준일 때(예: FiQA의 nomic-1.5 dense vs hybrid-titan) 풀 추가 순서에 따라 순서가 뒤바뀔 수 있음.
- 도메인 특이 qrels 괴리: TREC-COVID처럼 인간 전문가가 빡빡하게 채점한 의학 도메인에서는 LLM 일반 심사위원과 qrels의 순서 일치율이 76–84%로 떨어짐.
- 절대 점수 보정 실패: nDCG 점수가 +51%(FiQA), recall이 +161%(TREC-COVID) 등 데이터셋에 따라 절대값이 체계적으로 부풀려지거나 깎여, 벤치마크 간 절대 비교에 그대로 사용하면 오해 소지.
- 심사위원 모델 deprecation: 고정된 체크포인트를 쓰므로 심사 모델이 사라지면 누적된 풀의 의미적 연속성이 깨지고 재채점이 필요해짐.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### RAG 검색 모델 선택을 위한 증분 풀링 벤치마크 도입

장기 기억을 쓰는 RAG 에이전트라면 retrieval 단의 후보 임베딩을 N개로 모아 동일 top-K로 retrieve하고, 합집합 풀을 LLM 심사위원(GPT-4.1급, temperature 0, JSON 출력)으로 한 번만 채점한다. 이후 vendor가 새 임베딩을 내놓을 때마다 그 시스템이 기존 풀에 기여하지 않은 문서만 추가 채점해 매번 같은 풀 위에서 즉시 비교한다. 본 논문의 ∆C_{N+1} = Σ|R_N+1(q) \ P(q)| 공식을 그대로 쓰면, 4.9× 비용 절감(논문 §7.3) 효과를 동일한 구조에서 얻을 수 있다.

**적용 지점** — RAG 검색 모델 벤치마크 단계 (임베딩 후보 비교)

**기대 효과** — 신규 임베딩당 한계 채점만 발생, 65–80% 판정 재사용, nDCG@10 순위가 gold qrels와 ρ 0.69–0.95로 일치 (논문 §5.1)

### 부트스트랩 스왑 확률을 '사실상 동률' 품질 게이트로 사용

장기 기억 회수 단계에서 후보 리랭커/리트리버 A·B의 순위를 비교할 때, 단순 점수 차로 'A 승'이라고 단정하지 말고 B=10,000 질의 재추출 부트스트랩으로 두 시스템의 순서가 뒤바뀔 확률을 잰다. p_swap > 5%면 '사실상 동률'로 표시해 의사결정 보류 큐에 넣고, latency·비용·governance 같은 2차 기준으로만 결정한다. 본 논문의 Appendix A 부트스트랩 절차를 그대로 재사용하면, 거짓 정밀한 순위 차이(∆ < 0.001, §5.4)를 사람이 오인하는 사고를 줄일 수 있다.

**적용 지점** — 검색/리랭킹 모델 선택 시 품질 게이트

**기대 효과** — ∆nDCG < 0.001 수준의 사실상 동률 시스템 쌍을 자동 식별, 잘못된 미세 우위 주장 차단 (논문 §5.4)

### 고정 심사위원 + JSON 출력 기반 재현 가능한 평가 하네스

에이전트 하네스에서 외부 LLM을 평가·검증 호출기로 쓸 때, 모델명을 구체적 체크포인트(예: gpt-4.1-2025-04-14)까지 고정하고 temperature 0, JSON 스키마 출력, 동일 프롬프트를 모든 호출에 강제한다. 본 논문 §4.3의 일관성 측정(93–96% exact agreement, κ=0.84–0.90)을 근거로 '같은 조건에서 같은 결과'가 보장되는 호출 패턴을 표준화한다. 심사 모델이 deprecate되면 §4.3의 표본 재채점 절차를 자동화해 연속성을 명시적으로 확인한다.

**적용 지점** — 에이전트의 LLM-as-judge 평가 호출 단계

**기대 효과** — 장기간 누적 평가의 재현성 확보, 심사위원 드리프트 자동 검출 가능 (논문 §4.3)

### 풀 재사용으로 후속 분석 비용을 0에 수렴시키기

RAG retrieval 단계의 1차 모델 선택 프로젝트에서 766K 규모의 풀을 만들었다면, 그 풀은 이미 '차원이 hybrid에서 의미가 있는가', '키워드 변환 쿼리가 더 어려운가' 같은 후속 분석의 입력으로도 동시에 작동한다. 본 논문 §7.5가 보고한 production 사례가 직접적 근거로, 처음에 계획하지 않았던 분석들이 추가 LLM 비용 0으로 가능해진다. 따라서 풀을 평가 '결과'가 아닌 '자산'으로 다루는 데이터 거버넌스가 필요하다.

**적용 지점** — RAG 검색 평가 데이터 거버넌스 / 재사용 가능한 평가 자산

**기대 효과** — 사후 분석당 추가 LLM 비용 0, 후속 비교 질문 즉시 응답 가능 (논문 §7.5)
