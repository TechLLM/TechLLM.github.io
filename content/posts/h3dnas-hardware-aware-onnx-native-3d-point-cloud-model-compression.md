원본 학습 코드가 없는 ONNX 파일 하나로 3D 점군 인식 모델을 자동 축소·가속하는 도구를 만들었다.

**무엇이 문제였나** — 문제: AI 모델을 소형 보드(Jetson 등)에 올리려면 압축이 필요한데, 벤더가 주는 모델은 ONNX 바이너리일 뿐 원본 코드가 없어 기존 압축 도구를 못 쓴다.
**어떻게 풀었나** — 해결: ONNX 그래프만 들여다보고 어디를 줄여도 안전한지 미리 계산한 뒤, 라벨 없이 점수 매기고 점진적으로 구조를 변형해 자동으로 작은 모델을 만든다.
**그래서 뭐가 좋아졌나** — 결과: 정확도 손실을 거의 0에 가깝게 유지하면서 모델 크기를 절반 가까이 줄이고 추론 속도를 최대 2배까지 끌어올렸다.

> 레고 설명서 없이 완성된 레고 작품을 보고, 어떤 블록을 빼도 무너지지 않는지 계산한 뒤 가장 영향 없는 블록부터 안전하게 빼는 작업과 비슷하다. 빼는 것만으로 부족하면 비싼 블록을 싸고 작은 블록 여러 개로 바꿔 끼우는 변형까지 시도한다.

## 논문 정보

Anchit Mulye, Rhythm Baghel, Sujay Kumar Ingle, Hardik Jain · Indian Institute of Technology Jodhpur · arXiv preprint (arXiv:2609.02684v1) · 2026

## 왜 중요한가

현업에서 배포되는 AI 모델은 원본 코드가 없는 경우가 많다. 이 연구는 그 상황을 가정한 첫 실용적 압축 파이프라인을 제시해, 어떤 AI 모델이든 ONNX만 있으면 누구나 같은 방식으로 경량화할 수 있는 기반을 마련했다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| PointNet 파라미터 감소 | **65.5%** | ONNX 바이너리에서 베이스라인 대비 축소 비율 (3.46M → 1.19M 파라미터) |
| PointNet 추론 속도 향상 | **1.99×** | ORT CPU P50 레이턴시 기준 베이스라인 대비 (11.98ms → 6.02ms) |
| PointNet++ 정확도 변화 | **+0.08pp** | 압축 후 베이스라인 대비 정확도 변화 (91.90% → 91.98%, 압축이 오히려 성능 상승) |
| CDG 토폴로지 분석 시간 | **<1초** | ONNX 그래프만으로 압축 가능성(ρf) 계산에 소요되는 시간, O(|V|+|E|) 복잡도 |

## 어떻게 동작하나

H3DNAS는 ONNX 그래프를 직접 읽고 변형·가지치기·평가하는 프레임워크로, 학습 프레임워크 API를 호출하지 않는 것이 핵심 제약이다. 중심에는 채널 의존 그래프(CDG)가 있으며, ONNX 연산자를 채널 생성(CG)·투명(CT)·구속(CC)·종결(CX) 네 부류로 분류하고 다섯 가지 잠금 규칙(R1–R5)을 적용해 자유롭게 줄일 수 있는 노드를 식별한다. 이를 통해 자유 파라미터 비율 ρf가 그래프 토폴로지만으로 결정되는 토폴로지 불변량임을 증명해 채널 가지치기의 안전 상한을 사전에 제공한다. 2단계 계층적 탐색은 Stage 1에서 L1-중요도 기반 채널 선택과 출력 충실도(output fidelity, 코사인 유사도 기반 zero-shot 프록시, N=32 무작위 입력, 상위 K=15만 통과)로 후보를 압축하고, Stage 2에서 GhostConv 구조 변이를 통해 압축 한계를 더 밀어붙인다. 하드웨어 제약(파라미터·FLOPs·모델 크기·레이턴시)을 탐색 루프에 통합해 배포 예산을 만족하는 파레토 최적 모델을 자동 산출하며, 미세 조정은 onnx2torch로 ONNX에서 재구성한 모델로 수행한다.

핵심 수식:

```
\rho_f(G) = \frac{\sum_{n \in F} |\Theta_n|}{\sum_{n \in V_{conv}} |\Theta_n|}
```

ρf는 자유롭게 가지치기 가능한 노드 집합 F의 파라미터 합(|Θₙ|)을 전체 Conv/Gemm 노드 V_conv의 파라미터 합으로 나눈 값으로, 그래프 토폴로지만으로 결정되는 채널 가지치기의 안전 상한을 나타낸다.

## 한계와 주의할 점

- 레이턴시 측정이 OnnxRuntime CPU 4-thread에서 수행되어 실제 Jetson GPU 성능과 직접 일치하지 않는다. 보충 자료 Table 14에 TensorRT FP16(1.03~1.45×) 검증이 포함되긴 하나, 메인 결과의 1.29~1.99× 수치는 CPU-ORT 측정값이다.
- GhostConv Stage 2는 아키텍처에 따라 효과가 들쭉날쭉하다. PointNet에서는 +0.34× 추가 속도 향상을 주지만 PointMLP에서는 R2 잔차 결합이 21/40 노드를 잠가 정확도 -0.29pp 추가 손실과 함께 속도도 감소한다.
- Level 2 구조 변형(예: depthwise 분해)은 가중치 재초기화가 필요해 현 구현에서 지원되지 않으며, 더 공격적인 압축 기회가 차단된다.
- 어텐션 헤드 분할이 R1/R2 규칙에 의해 채널 가지치기로는 줄일 수 없어, PCT(ρf=12.34%)·PTv3(ρf=13.97%, 단 본문 Table 3 및 보충자료에서는 7.05%/7.0%로 기록되어 표 간 불일치가 있음) 같은 트랜스포머 기반 점군 모델은 채널 가지치기만으로는 의미 있는 압축이 불가능하다.
- onnx2torch로의 재구성이 지원하지 않는 커스텀 연산자를 포함한 모델은 미세 조정이 불가능하며, PTv3의 Reshape 상수 노드처럼 채널 차원을 그래프에 굽어박은 패턴은 ORT shape mismatch를 일으켜 PTv3 압축이 실제로는 연기(deferred)되었다.
- 본문 Table 5의 PointNet++ 속도 향상(2.82×~3.38×)이 Table 4의 1.29×와 크게 어긋나는 등 표 간 수치 일관성이 일부 부족하다.
- ρf가 15% 미만인 아키텍처(PCT 12.34%, PTv3 13.97%)에서는 채널 가지치기가 거의 효과가 없으며, 시스템은 이를 감지해 양자화나 어텐션 헤드 가지치기로 방향을 전환해야 한다.
- PointMLP처럼 잔차 Add 결합(R2)이 21/40 노드에서 발생하는 모델에서 GhostConv Stage 2는 새 Concat 의존성을 도입해 정확도와 속도 모두를 악화시키며, Stage 1 단독 사용이 권장된다.
- Jetson Orin Nano 8GB의 CPU ORT 레이턴시만 측정하므로, GPU·DLA·다른 엣지 디바이스에서의 실제 레이턴시 순위가 뒤바뀔 가능성이 있다.
- Reshape 상수 노드나 어텐션 헤드 차원을 그래프에 직렬화해 박아둔 모델(예: PTv3)은 채널 변경 시 ORT가 shape mismatch로 실패해 가지치기 자체가 진행되지 않는다.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### 출력 충실도를 라벨 없는 재순위 모델 품질 게이트로 사용

장기 기억을 쓰는 에이전트의 RAG 파이프라인에서는 재순위 모델을 더 작은 변종으로 교체하는 일이 잦다. H3DNAS의 Stage 1 출력 충실도(output fidelity, 본문 3.3절)는 학습 데이터 없이 N=32개의 랜덤 입력에 대한 베이스라인과 가지치기 모델의 로짓 코사인 유사도를 측정해, SWAP-Score 같은 기존 zero-shot 프록시가 50% 이상 압축에서 신호가 붕괴하는 문제를 회피한다. 실제 적용 시 (1) 교체 전후 모델의 무작위 입력에 대한 충실도 점수를 측정하고, (2) 임계값(예: 0.95) 미만이면 도입을 보류해 라벨된 평가셋 없이도 안전하게 압축 모델을 거른다는 단계로 옮기면 된다. 본문 2절 Related Work의 SWAP-Score 한계 분석과 3.3절 Stage 1의 출력 충실도 정의를 근거로 한다.

**적용 지점** — RAG 재순위 단계의 모델 품질 검증

**기대 효과** — SWAP-Score가 50% 이상 압축에서 신호가 붕괴하는 문제를, 출력 충실도가 안정적으로 보완해 라벨 없는 환경에서도 압축 모델 도입 판정을 가능하게 함 (논문 2절, 3.3절 Stage 1).

### CDG 식 프리체크로 에이전트 임베딩 모델의 압축 적합성 사전 판정

H3DNAS의 CDG 정리(Theorem 1, 본문 3.2절)는 ONNX 그래프의 노드 분포만으로 ρf를 O(|V|+|E|)에 계산해 채널 가지치기의 안전 상한을 보장한다. 장기 기억 회수 단계에서 임베딩 모델을 경량화하려 할 때, 이 프리체크를 임베더·인코더 ONNX에 그대로 돌려 (1) ρf < 10%이면 채널 가지치기를 시도하지 않고 곧바로 양자화로 안내하고, (2) ρf > 50%이면 본격적 압축 탐색을 개시하는 식의 의사결정 분기를 둘 수 있다. 본문 5절 Discussion은 EfficientNet-B0에서 ρf < 10%로 판정해 양자화로 안내하는 사례를 제시하고, 보충자료 Table 17의 EfficientNet-Lite(ρf=6.3%)가 동일 패턴을 보여주며, 이는 RAG의 임베더 선택 단계에 그대로 이식 가능하다.

**적용 지점** — 에이전트 임베딩/인코더 모델의 압축 전 feasibility 판정

**기대 효과** — 잠재적으로 압축 불가능한 모델에 대한 무의미한 실험을 사전에 차단해, 양자화 등 대안 경로로 자동 우회 (논문 5절, 보충자료 Table 17).

### 디바이스 예산을 명시한 파레토 탐색으로 엣지 에이전트 컴포넌트 자동 선택

H3DNAS의 HardwareConstraints 통합(본문 3.4절)은 후보별 FLOPs·파라미터·모델 크기·레이턴시를 탐색 루프 내에서 즉시 검사해 예산을 넘는 후보를 파레토에서 제외한다. 엣지에서 동작하는 에이전트가 보조 분류기·재산정 모델 등 다수의 소형 모델을 운용할 때, 동일 파레토 패턴을 적용해 (1) 디바이스 예산(예: 메모리 상한, 응답 지연 상한)을 하드 리미트로 선언하고, (2) 정확도 우선/균형/압축 우선 세 가지 운영점 후보를 단일 NAS 실행으로 추출하면, 디바이스별로 별도 실험을 돌리지 않고도 다양한 엣지 타깃에 동시 대응할 수 있다. 논문 Table 5의 PointNet 압축 우선(79.4% 감소, -0.61pp) 같은 극단점까지 한 번에 얻는 것이 핵심이다.

**적용 지점** — 엣지 디바이스에 배포되는 에이전트 보조 모델의 다중 운영점 산출

**기대 효과** — 단일 탐색 실행으로 정확도 우선·균형·압축 우선 3개 운영점까지 한 번에 추출, 디바이스별 별도 실험 불필요 (논문 Table 5, 3.4절).

## 단계별 도입 로드맵

| 단계 | 목표 | 액션 | 기대 효과 |
|---|---|---|---|
| Phase 1 — 파일럿 검증 | 보유 ONNX 모델에 대해 CDG 토폴로지 분석을 적용해 압축 가능성과 압축 구간을 사전 분류 | 1) 주요 3D 점군 모델의 ONNX 파일을 모아 CDG 분석 스크립트 실행, 2) ρf와 자유/구속 노드 분포를 표로 정리, 3) 압축 불가로 판정된 모델(PCT, PTv3 등)에 대한 양자화·헤드 가지치기 대안 검토 | 불필요한 압축 실험을 사전에 제거하고, 유망 모델에만 자원을 집중해 ROI 확보 |
| Phase 2 — 파이프라인 도입 | L1 채널 가지치기 + 출력 충실도 점수 + GhostConv Stage 2로 구성된 2단계 압축 파이프라인을 운영 추론 환경에 통합 | 1) H3DNAS 코드를 운영 중인 ONNX 처리 파이프라인과 연동, 2) 출력 충실도 점수의 임계값과 Top-K를 운영 환경에 맞게 튜닝, 3) 미세 조정에 사용할 라벨 없는 입력 샘플 수집 절차 마련 | 원본 코드 의존 없이 벤더 모델을 직접 경량화해 평균 50% 파라미터 절감과 1.5~2× 추론 속도 확보 |
| Phase 3 — 엣지 배포 및 상시 운영 | Jetson·모바일 SoC 등 다수 엣지 디바이스에 HardwareConstraints를 자동 적용하는 상시 압축 서비스로 전환 | 1) 디바이스별 FLOPs·메모리·레이턴시 예산 프로파일 자동화, 2) 파레토 최적 모델을 디바이스 펌웨어에 자동 배포, 3) 출력 충실도 회귀 모니터링을 CI에 통합해 압축 모델 품질 변동 감시 | 디바이스 종류에 무관하게 동일 정확도·지연 예산을 보장하는 모델 자동 출시 체계 구축 |
