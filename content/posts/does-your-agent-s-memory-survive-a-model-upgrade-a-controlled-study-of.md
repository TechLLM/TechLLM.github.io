AI 모델을 바꿨을 때 에이전트가 저장해둔 기억을 새 모델이 제대로 읽을 수 있는지는 기억을 어떤 모양으로 저장했는지에 크게 달려 있다는 연구.

**무엇이 문제였나** — 에이전트의 기억은 원본 대화, 검색용 조각, 요약 노트, 정해진 양식의 기록처럼 여러 방식으로 저장될 수 있다.
**어떻게 풀었나** — 논문은 두 모델과 48개의 실험용 이력을 써서, 모델을 바꾸거나 검색용 임베딩을 바꿀 때 정확도가 얼마나 달라지는지 비교했다.
**그래서 뭐가 좋아졌나** — 정해진 양식의 기록은 모델이 바뀌어도 거의 흔들리지 않았지만, 자유롭게 쓴 요약 노트는 누가 쓰고 누가 읽느냐에 따라 크게 달라졌고, 검색 인덱스를 구버전과 신버전으로 섞으면 품질이 조용히 떨어졌다.

> 한 직원이 자유롭게 적은 업무 메모를 새 직원이 읽는 상황과 비슷하다. '프로젝트 A 금요일'이라고만 적혀 있으면 새 직원이 뜻을 헷갈릴 수 있지만, '프로젝트명 | 마감일 | 출처'처럼 정해진 칸에 적힌 기록은 더 일관되게 읽힌다. 검색 시스템도 마찬가지로, 낡은 기준으로 만든 색인과 새 기준으로 만든 색인을 한 바구니에 섞으면 오류는 안 나도 좋은 결과를 놓칠 수 있다.

## 논문 정보

Ankit Goyal, Jaideep Ray · LinkedIn · arXiv preprint (arXiv:2609.05339) · 2026

## 왜 중요한가

실무에서 LLM 모델은 자주 바뀌지만, 에이전트가 쌓아온 기억은 오래 남는다. 기억이 조용히 망가지면 시스템은 계속 돌아가도 답변 정확도만 떨어질 수 있다. 그래서 모델 업그레이드 전에 어떤 기억 형식이 안전한지, 임베딩 인덱스를 어떻게 갈아끼워야 하는지, 복구를 위해 원본을 보관해야 하는지를 검증해야 한다.

## 핵심 지표

| 지표 | 값 | 설명 |
|---|---|---|
| KG-fixed 마이그레이션 정확도 변화 | **+0.0004 ± 0.0020정확도** | 고정 스키마 지식 그래프에서 작성자 모델 교체 시 정확도 변화(48 이력 평균). |
| NOTES 비대칭 정확도 변동 | **-13.28 ~ +9.91pp** | 모델 압축 노트에서 마이그레이션 방향별 정확도 차이(Qwen이 Llama 노트를 읽을 때 손실, Llama가 Qwen 노트를 읽을 때 이득). |
| 혼합 임베딩 인덱스 이득 | **4.96 / 11.90pp** | bge-large-en v1.0에서 v1.5로 전환할 때 50/50 혼합 인덱스가 확보한 정확도 이득 대비 완전 재임베딩 이득. |
| NOTES 손실의 작성 단계 기여 | **0.467 ± 0.014 (80%)정확도 결손** | NOTES의 전체 결손 0.584 ± 0.013 중 메모리 작성 단계가 차지한 절대 기여와 비율. |

## 어떻게 동작하나

연구는 (1) 무작위 답변 코드를 가진 48개의 합성 이력(각 160문항)을 사용하고, (2) 두 개의 동급 오픈웨이트 모델(Llama-3.1-8B-Instruct, Qwen2.5-7B-Instruct-1M)을 로컬 서빙하며, (3) 네 가지 메모리 형식(LC-RAW, RAG, NOTES, KG-fixed)에 대해 작성자 모델, 임베딩 모델, 복구 자원을 한 번에 하나씩만 바꾸며 통제 실험을 수행했다. 성능은 RPAS(Retained Performance After Swap)와 CTR(Cost-to-Recover)로 측정하고, 손실의 위치를 진단 분해(검색 단계 vs. 저장/작성 단계 vs. 판독 단계)로 분리한다. 통계 분석은 사전 고정된 4개 가설에 대해 1-표본 단측 t-검정과 Holm 보정을 적용했으며, 이후 10,000회 부트스트랩으로 같은 결론을 확인했다. 네 검정 중 H2(혼합 임베딩 인덱스가 완전 재임베딩보다 낮음)와 H7a(원본 이력 기반 복구가 store-only 복구보다 높음)만 5 pp 기준을 넘고 유의했다.

핵심 수식:

```
RPAS_s(A→B) = ( Perf(s, W=A, R=B) - chance ) / ( N_s(B) - chance )
```

A가 작성하고 B가 읽을 때의 정확도에서 우연 수준을 뺀 값을, B가 자기 메모리로 얻는 정확도에서 우연 수준을 뺀 값으로 나눈 비율. 1.0이면 손실 없음, 0.8이면 자기 메모리 성능의 80% 보존, 1 이상이면 상속 메모리가 자기 메모리보다 더 좋다는 뜻이다. 논문은 자기 메모리 점수가 우연 수준보다 최소 0.20 높을 때만 RPAS를 쓰도록 했고, 주 데이터에서는 이 기준에 걸린 설정이 없었다.

## 한계와 주의할 점

- 두 모델(Llama-3.1-8B, Qwen2.5-7B)의 단일 교차 패밀리 마이그레이션만 평가했으므로, 더 큰 모델·다른 패밀리·더 긴 이력에 일반화하기 어렵다.
- 합성 이력은 객관식 코드 기반의 160문항/이력 규모로, 실제 사용자 장기 대화의 주관성·잡음·수천 턴 규모를 충분히 반영하지 못한다.
- RAG 파이프라인은 단일 단계 dense retriever(cosine top-k=8, 리랭커·하이브리드 검색 없음)만 사용했기 때문에, 약 40% 검색 실패율을 모든 RAG 시스템의 본질적 한계라고 단정할 수 없다.
- KG-fixed는 본 워크로드의 이벤트 필드에서 직접 만든 스키마이므로, 스키마가 작업을 잘 표현하지 못하는 실제 업무에서는 같은 이식성 이점이 줄어들 수 있다.
- signed Git tag는 내부 분석 lock에 가깝고 완전한 공개 preregistration은 아니며, 계획된 부트스트랩은 최초 t-검정 결과를 본 뒤 후속 확인으로 실행됐다.
- NOTES의 비대칭 손실: Llama가 작성한 노트를 Qwen이 읽으면 정확도가 13.28 pp 떨어지고, 반대 방향은 9.91 pp 오른다. 평균이 0에 가까워도 한 방향은 심각할 수 있다.
- 임베딩 혼합 인덱스의 침묵 실패: 구·신 벡터가 같은 1024차원이라 차원 오류 없이 인덱스에 섞이지만, 동일 인덱스 안의 두 벡터 공간이 달라 검색 품질이 조용히 나빠진다.
- RAG 검색 누락: 본 설정에서 검색 단계가 전체 손실의 81%(0.364 ± 0.012)를 차지하며, 올바른 청크가 전달되지 않으면 판독 모델은 답을 만들 수 없다.
- NOTES 저장 단계의 정보 손실: 모델이 요약 시 사실 일부를 누락하면, 같은 메모리만으로 다시 쓰는 store-only 복구는 어떤 예산에서도 90% 복구 목표에 도달하지 못했다.

## 시스템 적용 아이디어

논문의 기법을 비슷한 구조를 가진 시스템에 옮길 때의 적용 지점이다.

### 임베딩 버전 분리 인덱스 + 라우터 기반 점진 전환 게이트

장기 기억을 RAG로 운영하는 시스템이라면, 임베딩 모델 업그레이드 시 인덱스 하나에 구·신 벡터를 섞지 말고 '임베딩 버전' 필드가 붙은 별도 인덱스를 만든다. 질의 시 라우터가 해당 인덱스만 조회하게 하고, 신 모델로 재임베딩이 끝난 청크에 새 버전 태그를 붙여 점진적으로 옮긴다. 본 연구의 H2 결과(혼합 인덱스가 11.90 pp 중 4.96 pp만 확보)가 이 격리 구조의 정당성을 직접 뒷받침한다.

**적용 지점** — RAG 검색 인덱스 및 재순위 단계

**기대 효과** — 본 실험과 같은 조건에서는 혼합 인덱스의 4.96 pp 이득 대신 완전 재임베딩의 11.90 pp 이득에 가까운 성능을 목표로 할 수 있다.

### 방향별 마이그레이션 회귀 테스트 4종 세트

장기 기억을 가진 에이전트의 배포 파이프라인이라면, 메모리 정확도 테스트를 항상 '자기 메모리 대조군'과 '상속 메모리 두 방향(A→B, B→A)'으로 구성한다. RPAS와 직접 정확도 차이를 함께 보고, 두 방향 중 한쪽이라도 허용 기준을 넘게 나빠지면 배포를 막는다. 본 연구는 Llama↔Qwen NOTES에서 +9.91 pp와 -13.28 pp라는 반대 부호 효과가 평균에서 상쇄되는 현상을 보였다.

**적용 지점** — 에이전트 모델 업그레이드 배포 게이트

**기대 효과** — 방향별 치명적 손실(13.28 pp)을 사전에 드러내고 평균 지표가 0에 가까워 보이는 착시를 줄인다.

### 고정 스키마 메모리 레이어를 우선 적용 대상으로 격상

장기 메모리 시스템이라면, 모델이 자유 형식으로 요약·작성하는 노트 채널과 별도로, 사용자 사실/약속/결정 같은 핵심 항목을 정해진 스키마(S-P-O + 시점 + 출처)의 정형 레코드로 저장하는 채널을 둔다. 본 연구의 KG-fixed는 작성 모델이 바뀌어도 +0.0004 ± 0.0020의 정확도 변동만 보였고, 본 워크로드에서 Llama 0.8456, Qwen 0.9878 수준의 own-store 정확도를 보였다. 단, 이 결과는 작업에 잘 맞는 고정 스키마에서 얻어진 것이다.

**적용 지점** — 에이전트 장기 기억 저장 형식 선택

**기대 효과** — 스키마가 작업을 잘 표현하는 경우 마이그레이션 시 작성 모델 의존성을 크게 줄일 수 있다.

### 원본 이력 보존형 복구 파이프라인 사전 측정

장기 기억을 쓰는 에이전트라면, 압축 노트와 별도로 원본 대화 로그를 보존하되, 복구에 쓸 모델 자체로 사전에 NOTES 재요약을 돌려 90%·95%·99% 복구 성공률과 비용을 측정한다. 본 연구는 같은 원본을 두고도 Qwen은 34/48에서 90% 복구(성공 사례의 중앙 비용 약 $0.76)를 달성한 반면 Llama는 0/48로 출력 한도 초과 때문에 실패해, 복구 가능성이 모델과 자원 한도에 강하게 의존함을 보였다.

**적용 지점** — 에이전트 장기 기억 복구 및 재요약 단계

**기대 효과** — NOTES 손상 시 원본 이력이 없으면 불가능한 복구 경로를 확보하되, 실제 성공률은 복구 모델과 예산으로 사전 검증한다.

### 손실 단계 진단 루틴: 검색→저장→판독 분해 자동화

에이전트 메모리 회수 파이프라인이라면, 정확도 회귀가 감지될 때 자동으로 (1) 정답이 포함된 저장 청크를 직접 주입, (2) 원본 이벤트를 주입, (3) 정상 경로와 비교하는 진단을 돌리고 손실이 어느 단계에 집중되는지 분해한다. 본 연구는 NOTES에서는 작성 단계가 손실의 80%(0.467 ± 0.014), RAG에서는 검색 단계가 81%(0.364 ± 0.012)를 차지한다는 점을 보였다.

**적용 지점** — 에이전트 메모리 회수 실패 진단 및 자가검증 단계

**기대 효과** — NOTES는 재요약/작성 품질 개선, RAG는 청킹/인덱스/랭킹 개선으로 먼저 라우팅해 불필요한 판독 모델 교체를 줄인다.

## 단계별 도입 로드맵

| 단계 | 목표 | 액션 | 기대 효과 |
|---|---|---|---|
| Phase 1 | 메모리·임베딩 자산의 현황 진단과 마이그레이션 위험 프로파일링 | 운영 중인 메모리 형식(원본/RAG/NOTES/KG) 분포와 임베딩 모델 버전을 인벤토리화하고, 각 저장소에 '작성 모델·임베딩 모델·청킹 방식·인덱스 버전' provenance 메타데이터를 부착한다. 20-probe 수준의 빠른 마이그레이션 체크(MAE 약 0.10)는 위험 후보를 찾는 조기 경보로 쓰고, 최종 승인에는 전체 평가를 적용한다. | 어떤 저장소가 모델 교체에 취약한지 데이터 기반으로 식별하고, 작은 효과나 형식 간 차이는 빠른 체크만으로 승인하지 않게 만든다. |
| Phase 2 | 이식성 높은 스키마로의 정규화와 임베딩 인덱스 격리 | 사용자 사실·약속·작업 상태를 NOTES만으로 보관하지 말고, 정해진 스키마의 S-P-O 레코드 또는 키-값 레코드로 별도 저장한다. 새 임베딩 모델 도입 시에는 별도 인덱스를 구축한 뒤 일괄 전환한다. 점진 전환이 불가피한 경우 인덱스 버전을 메타로 태깅하고 라우터로 두 벡터 공간을 격리한다. | 본 논문의 KG-fixed 결과처럼 잘 맞는 스키마에서는 마이그레이션 정확도 변동을 매우 작게 제한할 수 있고, 임베딩 업그레이드에서는 혼합 인덱스가 잃는 잠재 이득을 줄일 수 있다. |
| Phase 3 | 원본 보존·복구 경로·방향별 마이그레이션 테스트 자동화 | 정책 허용 시 원본 이력을 암호화·접근 제한·삭제 기한과 함께 보존하고, 실제 복구 모델로 90/95/99% 복구 성공률과 비용을 사전 측정한다. 모델 스왑 시 A→B와 B→A 두 방향 모두 평가하도록 CI 게이트를 추가하고, 회귀가 발생하면 NOTES는 작성/요약 단계, RAG는 검색/인덱싱 단계부터 진단한다. | 압축 메모리 손상 시 복구 가능 여부를 배포 전에 확인하고, 평균 지표에 가려지는 방향별 마이그레이션 회귀를 차단한다. |
